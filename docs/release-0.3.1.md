# AISpa 0.3.1

- Агент обязан открыть видимый дашборд во встроенной панели сразу после init,
  после resume и при возвращении к проекту, до содержательной работы.
- Init/resume выдают requiredHostActions; dashboard start возвращает точный
  URL проверенной локальной службы. Compact не теряет эти указания.
- Повторное открытие использует прежнюю вкладку, когда host это поддерживает.
  Временную вкладку сохраняют до окончания ответа. Queued не считается открытием.
- Resume выполняется отдельно от batch: следующие действия ждут открытия UI.
- Старые активные прогоны продолжаются закреплённым runtime; завершённая
  0.3.0 читается как история без переноса прежних PASS.

Исправлено чтение UTF-8 вывода в тестах проектных документов на Windows;
кодировку больше не определяет системная локаль.

## Живые этапы

- Обязательный start до первой правки: назначение и реализация различаются.
- В задачах видны роль, среда и время назначения текущего участника.
- Progress begin/end отмечает подготовку, сверку волн и итоговые этапы; часы
  учитывают явные паузы, не влияют на PASS и не выдаются за время модели.
- Проверка чистого клона отображается с таймером; неизвестная activity не
  скрывает текущий этап. Лента сохраняет задачу/роль назначения и правильное
  время значимого события.

Python не управляет встроенным браузером. Его открывает нативный инструмент
агента; в терминальном клиенте без такой поверхности сообщается ограничение.
Системный браузер не используется как незаметная замена.

Проверено реальное видимое открытие в Codex и контракт CLI на синтетических
данных. Новых полных модельных прогонов нет. [Протокол](validation-0.3.1.md).
