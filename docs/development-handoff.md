# Передача разработки AISpa

Этот документ относится к рабочей ветке исходников. Стабильный выпуск,
закреплённые runtime начатых прогонов и результаты внешних интеграций
учитываются отдельно в [текущем статусе](status.md).

## Быстрый запуск

Нужны Python 3.11+, Git и Node 18+ для проверки панели. Сторонних
Python-зависимостей у движка нет. Команды выполняются из корня репозитория:

```sh
python3 -B -m unittest discover -s tests -v
node --test tests/dashboard.test.cjs
```

Первая команда проверяет контракты Python; вторая — доставленный скрипт панели.
На Windows используйте тот же установленный Python 3.11+ через `python -X utf8`
или `py -3 -X utf8`; результат нативной Windows подтверждается только
проверкой точного commit в CI.

Отдельная установка рабочего кандидата для этих проверок не требуется.
Отдельный прикладной запуск для этой проверки не требуется.
Рабочий сценарий навыка исполняется агентом с закреплённым runtime проекта;
успешные команды выше сами по себе не подтверждают модельный прогон,
видимый браузер или живые внешние материалы.

## Устройство

`skills/aispa/tools/aispa_core/store.py` хранит неизменные источники и
добавляемый журнал. `contracts.py` проверяет схемы и доказательства;
`workflow.py` и `team.py` управляют переходами и участниками. Панель читает
проверяемый снимок через `dashboard_reader.py` и `dashboard_server.py`,
а `display.py` формирует представление. Новая политика включается новым
`init`; уже начатый прогон продолжает свой закреплённый runtime.
Адресные maintenance readers проверяют разрешение ограниченным чтением и
сохраняют `runtimeDigest` между явными событиями выбора; это не меняет
закреплённую копию уже начатого прогона автоматически.

## Решения

Выбор: проверять рабочую ветку в исходниках и сохранять активные pinned runtime.
Альтернатива: заменить установленный навык или активный runtime текущим кандидатом.
Последствие: новая политика действует только в новых init; действующие прогоны сохраняют историю, а внешние интеграции требуют отдельных квитанций.

Выбор сохраняет историю и позволяет связать проверки с точным исходным
кандидатом. Публикация Release, установка и приёмка пользователя — отдельные
операции со своими доказательствами.

## Словарь

- **Кандидат** — конкретное состояние исходников и документации, к которому
  привязана проверка.
- **Основа (basis)** — контрольная сумма состояния задачи; при изменении
  источников прежний отчёт может устареть.
- **Закреплённый runtime (pin)** — копия движка, с которой начат прогон.
  Выпуск новой версии сам по себе её не заменяет.
- **Квитанция** — сохранённая запись фактической команды, назначения или
  наблюдения с привязкой к источнику. Наличие квитанции не доказывает смысл
  непроверенной внешней операции.

## Открытые обязательства

R11: живое использование FAQ уроком GetCourse, собственной платформой и Aiki
требует отдельных binding, delivery и visible read-back либо остаётся явным
блокером. Локальные тесты FAQ не закрывают эту интеграцию.

A10-D02: полный журнал хранит состояния, а большой прогон требует повторного
чтения; постоянный проверяемый индекс или delta history не реализованы.
