# Испытания и открытые ограничения · 0.1.0-alpha.3

## Автоматические проверки

Из корня: `python3 -B -m unittest discover -s tests -v`.
Нужны Python 3.11+ и Git; внешних Python-зависимостей нет.
Поведение JS: `node --test tests/dashboard.test.cjs`, Node 18+, без npm-пакетов.
Тесты выполняют доставляемый inline-скрипт в небольшой модели DOM; реальный
браузер дополнительно проверяется при изменении вёрстки.

| Уровень | Что проверяется |
|---|---|
| Хранилище | история, блокировка записи, изменение исходника, повреждённая запись, пути, снимок кода |
| Контракт | цитаты, обязательное ядро, полнота плана, зависимости, зоны, доказательства, устаревание |
| Сдача | отказ без проверок; отказ при непроверенном ядре; отдельный итог с второстепенным остатком |
| CLI | настоящий subprocess, коды ошибок, весь синтетический путь до finish, сохранённая версия движка |
| HTTP | локальная выдача HTML и JSON из текущего прогона |
| Время | старт/завершение, пауза, повторный запуск, диапазон оценки по волнам, отсутствие выдуманного ETA |
| Интерфейс | фильтры, безопасный текст, деморежим, ошибки связи, живые часы и правильные поля остатков |
| Команда задачи | карточки и реальные поля назначения, разные записанные участники, обязательные два раунда, repair, trace и отдельный acceptor |
| Зависимости | явный write/read порядок, транзитивные входы, наследование исторических доказательств через принятого потомка |
| Проектный контекст | сохранение правил, backup, три адаптера, override, конфликт Cursor, symlink/traversal, точные источники, ограниченная память и свежесть |
| Обновление | SemVer и Release-only выбор, offline, проверка manifest/ZIP, кандидат, согласие, CAS, backup/rollback, защита Git/runtime |
| Ресурсы Release | воспроизводимый пакет из точного commit, состав, версия, LICENSE и manifest без публикации |

В тестах независимый проверяющий **моделируется синтетическим отчётом**.
Это подтверждает обработку отчёта, а не независимость или качество модели.

Локальные результаты и отдельный нативный мини-пилот: [протокол alpha.3](validation-alpha.3.md).

## Проверить вручную до стабильного выпуска

Для Codex, Claude Code и Cursor отдельно:

1. Открытие установленного пакета: первым идёт update-check, затем выбор режима.
   Проверить отсутствие Release, offline и продолжение без установки.
2. Прогоны auto, important, interview: вопросы только на этапе брифа.
3. Малый реальный проект с 5–10 требованиями и хотя бы двумя волнами.
4. Одно забытое требование вне реестра: независимый проверяющий должен найти его.
5. Новая команда владельца в середине задачи: прежняя приёмка устаревает,
   старые слова остаются, изменения проходят новый план и сверку.
6. Потеря контекста и возобновление без повторного интервью.
7. Отсутствующий доступ: независимые задачи продолжаются, интеграция остаётся блокером.
8. Рабочее ядро с остатком: честный итог, остаток присутствует в следующем запуске.
9. Перезапуск для пересмотра решения агента: сохранённая история и новые доказательства.
10. Авторский дашборд: широкое и мобильное окно, длинные требования, ошибки сервера,
    устаревшее состояние, отсутствие противоречия между заголовком и данными.

11. Нативные отдельные worker, critic1, critic2, acceptor: записанные ID совпадают
    с ответами инструментов; свежесть контекстов подтверждается средой.
12. Второй критик запускается после первого PASS. После FAIL выполняется
    адресная перепроверка и repair, связанный с SHA/findings первого отчёта.
13. Второй FAIL блокирует попытку без третьего раунда. После финального ответа
    новые слова владельца открывают новую историю через new-attempt.
14. Приёмщик находит несоответствие исходной цитате и нарушение критерия предка,
    даже если исполнитель и критики считают результат достаточным.
15. Возобновление по context/memory и полным источникам; пользовательские
    AGENTS/CLAUDE/Cursor правила сохраняются, hand-edit конфликт не затирается.
16. После отдельного разрешения на будущий Release: проверка настоящих ресурсов
    GitHub, просмотр подготовленного кандидата, явная установка и откат в
    тестовой копии. Это не часть публикации текущей итерации.
17. Аварийный останов между переименованиями: сохранность соседнего backup,
    восстановление по receipt и отсутствие перезаписи активного runtime.

## Ограничения альфы

- Смысловое соответствие брифу и достоверность наблюдений не вычисляются по
  хешу. Нужны реальный сценарий и отдельный проверяющий. Поле `independent`
  фиксирует заявление процесса, не удостоверяет личность модели. Native ID и
  session записываются координатором; криптографической аутентификации агента нет.
- Цитата решения владельца проверяется на присутствие в сохранённом брифе.
  Кто произнёс слова и действительно ли это разрешение, проверяет агент по диалогу.
- Проверка кода учитывает Git-файлы и неигнорируемые новые файлы. Игнорируемые
  зависимости, внешние сервисы и данные проверяются отдельными сценариями.
  Для символической ссылки фиксируется сама ссылка, не внешнее содержимое.
- Git submodules пока отклоняются явно. Windows и особые сетевые файловые
  системы пока не входят в подтверждённый runtime.
- После аварийного завершения может остаться `.aispa/.lock`: сверить PID и
  отсутствие активного процесса, затем убрать только этот lock-файл.
  Повреждённый журнал нельзя автоматически заменить новым.
- Обновления доверяют опубликованным ресурсам фиксированного GitHub-репозитория
  и их хешам, без независимой подписи издателя. CAS защищает от изменения
  пакета после подготовки, но не обещает recovery после SIGKILL; порядок
  восстановления — [updates.md](updates.md).
- Автоматической миграции между версиями движка пока нет. Продолжать можно
  сохранённой копией runtime, новый прогон использует новую установленную версию.
- История локальных прогонов не публикуется автоматически. Архивирование и
  перенос приватных брифов между машинами требуют отдельной процедуры.
- В alpha.2 внедрён дизайн владельца; проверены узкие размеры 320/390 px и
  чтение тестового прогона движка. Проверка на реальных телефонах остаётся
  отдельным шагом. Внешние шрифты Google Fonts имеют системный fallback.
- Время — интервал между отмеченными событиями. Простой без явно записанной
  паузы включён в него. ETA — эвристика по завершённым задачам; точность на
  длительных реальных модельных прогонах ещё не измерена.

## Условие выпуска 1.0

Успешные автоматические проверки, подтверждённые модельные прогоны выбранных
сред, пользовательские испытания и отдельная команда владельца на выпуск.
Публичный main и номер alpha не заменяют это решение.
