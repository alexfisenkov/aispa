# Испытание условной критики AISpa на трёх новых проектах

Историческая батарея: её прерванные попытки и расходы сохранены неизменно.
Задачный путь WARN → ремонт → critic2 → приёмщик позднее подтверждён
[отдельным продолжением](validation-lean-service.md#узкое-продолжение-warn-ветки),
которое не завершало весь Queuelet и не исправляет итог этой батареи.
[Текущий статус и остатки](status.md).

21.10.2026 выполнены все шесть запланированных попыток. **Преимущество AISpa
по продуктивности не подтверждено.** Единственная пара с двумя завершёнными
продуктами — Pulsefold: оба приняты, референс быстрее и экономнее.
При этом у AISpa есть отклонение процесса. В остальных парах два запуска AISpa
оборвала перегрузка модели, а для Weavecfg обнаружено противоречие
инструкций теста о папке результата.
Общего рейтинга по трём проектам эти данные не дают.

Код AISpa закреплён до новых заданий и не менялся во время испытания.
[Регистрация](pilots/adaptive-review/paired-test/protocol.json),
[метрики](pilots/adaptive-review/paired-test/metrics.json),
[внешняя приёмка](pilots/adaptive-review/paired-test/acceptance.json).
Частные нативные журналы, исходники референса и продукты остаются в локальном
исследовательском архиве; здесь опубликованы только агрегаты и выводы.

## Результаты по проектам

| Проект | AISpa | Референс | Что можно заключить |
|---|---|---|---|
| Pulsefold, JSONL CLI | Продукт PASS: R1–R7, 47/47 пунктов | Продукт PASS: R1–R7, 47/47 пунктов | В этом опыте референс быстрее и экономнее; у AISpa отклонение по AGENTS.md |
| Queuelet, HTTP + SQLite | Прерван провайдером, финальной сдачи нет | Продукт PASS: R1–R7, 44/44 пункта; изоляция нарушена | Полной сопоставимой пары нет |
| Weavecfg, существующая библиотека | Прерван провайдером, финальной сдачи нет | Готовый код в candidate; сборщик проверил project, инструкции противоречивы | Продуктивность пары сравнить нельзя |

Число пунктов включает автоматические проверки и фиксированные ручные пункты.
Это конечное покрытие заданного брифа, а не доказательство отсутствия любых ошибок.

Все проверки выполнялись после заморозки. Собственные тесты запускались
по фактическим командам README в отдельных чистых клонах: Pulsefold AISpa —
19 тестов и отдельный пример; Pulsefold референса — 6 тестов и py_compile;
Queuelet референса — 13 тестов и повтор указанного в README тестового файла.
Во всех этих командах код возврата 0. У трёх остальных основных снимков нет
README с командой тестов: собственные тесты отмечены NOT_RUN, команда не угадана.

Внешний инструмент проверял новые точные клоны независимо от собственных тестов.
Два свежих проверяющих на каждую пару читали A/B в противоположном порядке,
не видели результатов запуска, метрик или ключа соответствия. По всем
фиксированным ручным пунктам они согласились. Их статическое чтение не выдано
за runtime PASS; ручные пункты добавлены отдельным проходом внешней приёмки.
Слепота LIMITED: README и .gitignore сохранены без редактирования и содержат
подсказки происхождения.

Время — от dispatch до нативного завершения: оно включает служебные фазы
и интервал до начала нативной работы. Токены подготовки испытания, контроллера,
коротких проверок доступности модели и внешней оценки исключены у обоих
методов. В JSON отдельно сохранены длительность нативного интервала
и задержка dispatch. У прерванного Weavecfg AISpa эта задержка составила
176,486 с; причина задержки не выводится из usage, время этой попытки
не используется для сравнения.
Все оркестраторы и потомки использовали `gpt-6.1-sol/high`; 39 контекстов.
Reasoning входит в output и второй раз не прибавляется. Денежный счёт
провайдера не измерен; токены кэша не приравниваются по цене к остальному входу.

Описательное отношение AISpa/референс в Pulsefold: **1,85× времени,
2,42× входа вне кэша, 2,66× выхода** при одинаковом результате R1–R7.
Это одна пара с оговоркой процесса, без статистического или причинного вывода.
Новые задачи отличаются от прошлого опыта: эти числа не измеряют экономию
новой версии относительно старой. Общую сумму для рейтинга продуктивности
не считаем: объём завершённой работы различается.

## Сбои и отклонения сохранены

- **Pulsefold AISpa:** к исходному AGENTS.md добавлены управляемые ссылки.
  Исходные 3736 байт сохранены точным префиксом, добавлен 1361 байт; бриф и
  PROCESS не изменены. Сырой контроль неизменности остаётся FAIL. Продуктовый
  PASS не снимает отклонение протокола.
- **Queuelet референса:** общий вызов списка агентов раскрыл финальный ответ
  предыдущего Pulsefold референса, включая перечень проверок и решений.
  Вызов и ответ сохранены. Заявление об отсутствии использования не доказывает
  отсутствие влияния. После этого дано только напоминание ограничить список
  собственным поддеревом; последующие попытки получили его до запуска.
  Момент напоминания несимметричен. Проверены записи всех 39 контекстов;
  это единственный найденный вызов list_agents без фильтра.
- **Queuelet AISpa:** первый критик выдал WARN, исполнитель сделал ремонт
  и сообщил 15 собственных тестов. Провайдер оборвал оркестратор до второго
  критика, отдельной приёмки и финального коммита. Незакоммиченный код сохранён,
  но его нельзя считать принятой сдачей или завершённым прогоном новой ветки.
- **Weavecfg AISpa:** оркестратор и проверяющий покрытия получили ошибку
  перегрузки. Контроллер остановил оставшегося исполнителя и принадлежащий
  попытке сервер. Продукт не сдан. Скрытых продолжений или повторов нет.
- **Weavecfg референса:** итоговый ответ указал `5e07e47449b2e4320f515f8cc773e2e32a163834`
  в соседней папке candidate. Заданная папка project сохранила
  `4e40fb4b4db2333e3a3313df39e4ae698188e92d` с исходной реализацией и процессными
  документами. Основная оценка проверяет именно заранее заданную папку;
  capture имеет статус invalid. Общий PROCESS требовал копировать стартер в
  новую candidate, индивидуальные INSTRUCTIONS называли project, а сборщик
  снимал только project. Связь папок не была однозначно определена. Поэтому
  несовпадение нельзя уверенно приписать ошибке исполнителя или качеству
  референса: это дефект условий эксперимента. Оба снимка сохранены.

Для последнего случая отдельно, **после основной заморозки**, проверен чистый
клон точного заявленного SHA из сохранённого архива. Все 8 автоматических
пунктов прошли; ручные пункты R5/R7 отдельно не выполнялись, общий статус
NOT_CHECKED. Это полезное свидетельство работоспособности написанного кода,
но не подмена основной сдачи и не новый модельный запуск.

У двух прерванных AISpa основные frozen HEAD остались исходными. Их сырые
внешние проверки закономерно дают FAIL по отсутствующей реализации; это
**не оценка качества сданного продукта**, потому что сдачи нет. Причина
прерывания — наблюдаемая ошибка провайдера. Нельзя ни засчитать этим попыткам
PASS, ни превратить их в два доказанных поражения алгоритма разработки.

## Проверка новой цепочки AISpa

Pulsefold подтвердил первый PASS → отдельный приёмщик без critic2:
вердикты отчётов, последовательность событий журнала и реальные нативные
запуски согласуются. Критик и приёмщик — разные участники; фиктивного второго
отчёта или участника нет.

Девять записей авторства фаз связаны с реальными нативными ID. Подготовку идеи,
исследование, разбор брифа и планирование выполнил один координатор;
некоторые проверочные фазы тоже используют одного допустимого автора.
Это адресная атрибуция работы, а не заявление о девяти независимых агентах
и не доказательство качества каждого документа само по себе.

## Сверка доказательств

Независимый методический аудит отчёта — PASS после уточнения конфликта папок
и определения времени. Пересчитаны токены всех 39 нативных журналов,
проверены их SHA, контрольные файлы времени и реальные параметры 33 запусков
дочерних агентов. Это подтверждает опубликованные числа, а не снимает
описанные ограничения эксперимента.

Контроллер отдельно проверил нативные вызовы шести внешних проверяющих:
разные ID, одна модель и настройки, чтение только своих обезличенных копий,
без запуска продукта или доступа к результатам других проверяющих.
Проверка публичного состава на секреты — PASS; частные журналы не публикуются.

## Что остаётся

Исправления движка проверены отдельно:
[локальные тесты и CI трёх ОС](validation-adaptive-review.md).
Эта батарея не подтверждает общего превосходства AISpa или экономии его
полного процесса. Следующий приоритет — сокращение подготовки и служебных
переходов при сохранении приёмки, затем новая заранее зарегистрированная пара
при устойчивой доступности модели. Условия должны однозначно фиксировать
папку итогового продукта и исключать чтение чужих итогов средствами среды.

Проверка полного модельного пути WARN → ремонт → critic2 → приёмщик остаётся
незавершённой из-за сбоя; библиотечные регрессии этой цепочки прошли.
Нативные прогоны Claude Code/Cursor и модельные прогоны на Windows не выполнялись;
Windows проверен инженерной CI. Новый Release и глобальная установка не делались.

## Зафиксированные до запуска условия

Кандидат AISpa — `7b39b9e33e9cf6d09af808f510dd5d6b4d2facec`; референс 2.1.0 —
`9fc898cbe941d5b8a369f1dd657e9119676eb44f`. Код кандидата закреплён до чтения
новых заданий основным исполнителем. Задания и скрытые проверки подготовлены
отдельным агентом, проверены независимо и не меняются во время испытания.

| Новый проект | Тип работы | Порядок |
|---|---|---|
| Pulsefold | JSONL CLI | AISpa, референс |
| Queuelet | HTTP-очередь с SQLite | Референс, AISpa |
| Weavecfg | Доработка существующей библиотеки конфигурации | AISpa, референс |

В каждой паре одинаковы исходный commit, бриф, Python 3.11, модель
`gpt-6.1-sol/high`, доступные инструменты и час на попытку. Прогоны идут
последовательно с новым контекстом; активных дочерних агентов не более двух.
Референс следует своим правилам; новая условная критика AISpa ему не навязывается.

После заморозки всех шести продуктов: одинаковая внешняя проверка чистых клонов,
собственные документированные тесты и два независимых чтения каждой пары
в противоположном порядке. Буквы A/B скрывают метод; если продукт сам раскрывает
его в README или коде, текст сохраняется и ограничение слепоты отмечается.

Все R1–R7 обязательны. Отсутствие процессной декларации COMPLETION.json не
считается автоматически дефектом продукта. Сбой проверяющего инструмента
не считается провалом продукта. Частичные и неуспешные попытки не исключаются.

Метрики берутся из нативных записей оркестратора и всех его потомков. Токены
кэша, вход вне кэша и выход различаются; это не расчёт денежного счёта.
Подготовка и внешняя оценка исключаются симметрично; пробелы измерения
указываются явно. Три пары по одной попытке не доказывают универсальное
или статистически подтверждённое превосходство. Результаты и ограничения приведены выше; исходная регистрация
сохранена в истории Git.

До первого dispatch внесена явная поправка сборки: генерируемые кэши
`__pycache__`, `.pyc` и `.DS_Store` исключаются одинаково из обоих пакетов
и их проверки. В Git референса найден один `.pyc`; первоначальные шесть
неиспользованных папок и манифест сохранены. Исходники, брифы, стартовые файлы
и oracle не менялись, модельных повторов — ноль. Поправка и новые SHA
зафиксированы в протоколе до запуска.
