# Дашборд AISpa · 0.1.0-alpha.7

Дашборд использует дизайн владельца Chrome & Graphite: шрифты Unbounded,
Onest и JetBrains Mono, графитовые карточки и хромовые акценты. В шапке —
утверждённый логотип мастерской, небольшая подпись «AI мастерская» и крупное
название AISpa. Логотип встроен как SVG; отдельный запрос к серверу школы
для его загрузки не нужен. Шаблон — `skills/aispa/assets/dashboard.html`.
Он самодостаточен, кроме необязательной загрузки шрифтов Google Fonts.

После текущей работы и времени показываются «Задачи по волнам»: здесь видно,
что уже принято, что выполняется и какую проверку проходит каждая задача.
Затем идут этапы проекта, требования, остатки и решения агента. Отдельный
блок четырёх сводных счётчиков удалён; существенные сведения остаются рядом
с соответствующими задачами, требованиями и остатками.

## Источник данных

Локальный сервер отвечает на `/status.json` свежим представлением журнала.
Чтение не ждёт блокировку длительной команды verify и не изменяет журнал.
Каждый HTTP-запрос использует отдельный экземпляр читателя; повреждённое
или неполное состояние даёт 409. Сервер не возвращает прежний успех вместо
ошибки. На диске `status.json` остаётся снимком последней команды CLI.

Интерфейс запрашивает состояние каждые пять секунд, часы обновляет раз в
секунду. Ошибка запроса или 15 секунд без подтверждённого ответа снимают
успешный заголовок и положительные отметки общих проверок; остаётся явно
подписанный последний снимок. Фильтры не могут вернуть старое «принято».
Таймеры фиксируются на последней подтверждённой отметке. Успешный ответ
восстанавливает отображение.

| Поле | Значение |
|---|---|
| `title`, `stage` | название и этап движка |
| `displayStage` | один из семи шагов интерфейса, выведенный из источников и проверок |
| `status`, `label` | результат, определённый движком |
| `gates` | актуальность покрытия, плана и приёмки |
| `requirements` | ядро, исходные требования, добавления, родитель и решение владельца |
| `tasks` | задачи, волны, общий статус, фаза, время и актуальность доказательств |
| `tasks[].phaseSteps` | пять фаз с подтверждёнными состояниями текущей попытки |
| `tasks[].phaseTiming` | часы текущей фазы либо `null`, когда время не записано или проверки устарели |
| `tasks[].phaseStale` | есть устаревшее подтверждение в цепочке фаз |
| `tasks[].proofCurrent` | актуальна ли приёмка завершённой задачи |
| `remaining.checks` | неуспешные условия текущей приёмки |
| `remaining.blockedTasks` | ID актуально заблокированных задач, даже до финала |
| `remaining.excluded` | ID требований, исключённых по записанному решению владельца |
| `remaining.unmapped` | пункты исходного брифа, не попавшие в реестр |
| `remainingAssessed` | есть ли текущий отчёт приёмки; отсутствие отчёта не означает отсутствие остатков |
| `activity` | выполняющаяся команда проверки, видимая до её завершения |
| `elapsedSeconds` | накопленное время прогона без отмеченных пауз |
| `estimate` | примерный диапазон оставшегося времени либо причина отсутствия оценки |
| `decisions` | решения агента |
| `updatedAt`, `observedAt` | последняя запись и последняя проверка актуальности |

## Фазы задачи

Общий `status` остаётся pending/running/blocked/completed. Внутри задачи
отдельно показаны пять фаз: реализация (`implementation`), первый критик
(`critic_1`), исправление (`repair`), второй критик (`critic_2`) и приёмщик
задачи (`task_acceptance`). `phaseSteps` содержит для каждой `id`, `label`
и `status`: pending/current/done/skipped/blocked/stale.

Отметки выводятся из сдачи исполнителя, отчётов двух критиков, исправления
и приёмки текущей попытки. Порядковый номер фазы сам по себе не доказывает
прохождение предыдущих. После первого PASS можно пропустить только исправление;
второй независимый критик обязателен в любом случае. Completed появляется
только после отдельного приёмщика задачи. Счётчик волны учитывает принятые
задачи с актуальными доказательствами, если движок передаёт `proofCurrent`.

Изменение проверяемых входов после сдачи или повреждение подтверждающего
артефакта делает прежние успешные отметки устаревшими. У выполняющейся задачи
текущая фаза также получает stale; интерфейс пишет «Проверки устарели» и скрывает её часы.
Законная правка во время repair после первого FAIL не объявляется устаревшей
только из-за ожидаемого изменения входов: новая проверка и repair ещё впереди.
Повреждённые доказательства это исключение не разрешает использовать.

Полная история ролей, нативных участников, попыток и отчётов остаётся в журнале
и `.aispa/context/progress.md`. Экран только отображает состояние; обходов
переходов и кнопки самостоятельного принятия задачи в нём нет. Приёмка задач
не заменяет итоговую приёмку всего проекта.

## Время

У задачи показаны общая длительность и длительность текущей измеренной фазы.
Команда start записывает startedAt и activeSince задачи и запускает её фазу.
Одна лишь подготовка плана или назначение роли часы не запускает. При переходе
текущая фаза меняется; `phaseTiming` содержит phase, startedAt, elapsedSeconds
и activeSince, пока интервал активен. Это часы текущей фазы, не полный отчёт
о длительности всех прежних фаз.

Complete и block останавливают активный интервал. Пауза прогона останавливает
его часы, часы задач и фаз; resume возобновляет их. Reset и повторная попытка
сохраняют уже потраченное общее время по ID задачи, новая фаза начинается
по фактическому start. Время включает ожидание инструментов и простой,
который не был отмечен паузой; это не CPU-время и не токены.

Для задач без общего времени показывается «Время не записано»; ожидающие
задачи подписаны «Ещё не начата». Если старый runtime не записывал часы фазы,
`phaseTiming` остаётся `null`: начало не восстанавливается из номера фазы,
времени файла или очередного чтения. При `phaseStale` часы фазы также скрыты;
записанное общее время задачи сохраняется. При потере связи часы всего экрана
не продолжают отсчёт по неподтверждённому состоянию.

После двух завершённых задач с измеренными длительностями берётся их медиана.
Нижняя оценка учитывает параллельные задачи одной волны, верхняя — возможное
последовательное исполнение. Добавляются запас неопределённости и резерв на
итоговую приёмку. Это ориентир, не обещание срока. Если задача превысила медиану,
её остаток не становится нулём автоматически. Блокер, пауза, недостаток данных
и итоговая проверка без известных сроков показываются словами вместо числа.

## Правдивость интерфейса

- `accepted` — приняты все действующие требования без остатков.
- `delivered_with_remaining` — ядро принято, остатки перечислены.
- `stale` — результат изменён, требуется новая проверка.
- `blocked`, `paused`, `cancelled` и потеря связи не выглядят как успешная сдача.
- «Реализовано по задачам» не означает «принято»; процента общей готовности нет.
- Пользовательские строки вставляются через textContent.
- `?demo` явно включает пример. `?status=accepted` без `demo` не влияет на живые
  данные. Демонстрационные фазы, таймеры и ETA не доказывают реальный прогон.

Новые прогоны используют поставленный runtime. Уже начатые продолжаются
закреплённой копией: обновление пакета не меняет их шаблон и часы задним числом.
