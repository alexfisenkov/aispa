# Данные для будущего дашборда

Владелец меняет внешний вид в `skills/aispa/assets/dashboard.html`.
Текущий HTML — простой временный экран, написанный для испытаний движка.

Источник интерфейса — `.aispa/status.json`, который строится из журнала.
Вёрстка не записывает состояние и не решает, что считать готовым.
После изменения файлов проекта команда `status` заново проверяет свежесть
приёмки. Локальный сервер также пересчитывает её при каждом запросе
`status.json`; при ошибке или занятом журнале возвращает 409, а не старый успех.
Сам файл `status.json`, прочитанный без сервера, остаётся сохранённым снимком.

| Поле | Значение |
|---|---|
| `title`, `stage` | название и текущий этап |
| `status`, `label` | фактическое состояние и готовая формулировка |
| `gates` | актуальность покрытия, плана и приёмки |
| `requirements` | требования, ядро, принадлежность к исходному заказу/добавлениям |
| `tasks` | задачи, вычисленные волны, статусы |
| `remaining` | неуспешные проверки, исключения по решению владельца, блокеры |
| `decisions` | решения, принятые агентом |
| `updatedAt` | время последней записи движка, не время загрузки браузера |
| `observedAt` | время последней проверки актуальности представления |

`accepted` — приняты все действующие требования, остатков нет.
`delivered_with_remaining` — ядро принято, остатки явно перечислены.
`stale` — ранее принятый результат изменился; требуется новая проверка.
`blocked`, `paused`, `cancelled` не должны выглядеть как успех.

У реализации отдельный признак `implementation`; он не является приёмкой.
Не выводить процент «всё готово» только из числа закрытых задач.
Произвольный пользовательский текст вставлять безопасно, например через
`textContent`. Новый интерфейс может менять структуру, цвета и число блоков,
сохраняя эти смысловые различия.
