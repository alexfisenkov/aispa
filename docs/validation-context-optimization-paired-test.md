# AISpa после оптимизации: три парных испытания

21.10.2026. Шесть запусков на одной модели `gpt-6.1-sol/high`.

**В этой батарее референс оказался продуктивнее:** он прошёл внешнюю приёмку
трёх продуктов, AISpa — одного. У референса есть неблокирующее замечание к
документации библиотеки. Во всех трёх парах он затратил меньше времени,
входных токенов вне кэша и выходных токенов. Это результат трёх малых
заданий, а не универсальный рейтинг навыков.

Оптимизация AISpa внедрена и реально использовалась. Два независимых круга
критики и отдельные приёмщики задач сохранились. Однако повтор CSV-задания
оказался дешевле **при худшем результате внешней приёмки**; подтверждённым
улучшением продуктивности это не считается.

## Что изменили и что испытывали

После опубликованной alpha.10 добавлены вычисляемые формы отчётов, краткие
ответы `--compact` с сохранённым полным оригиналом, стабильные адреса context
по SHA и уточнённый порядок финальных проверок. Поля оценки и evidence
по-прежнему заполняет проверяющий; валидаторы и бюджет критики не ослаблялись.
Логотип, «AI мастерская» и AISpa в шапке панели открывают
[публичный канал](https://t.me/masterskaya_video).

Код прошёл локальные проверки, два круга инженерной критики и
[финальную CI на Windows, macOS и Linux](https://github.com/alexfisenkov/aispa/actions/runs/39464558131).
Это подтверждает реализацию инструмента, но не безошибочность продуктов,
которые создаст модель. Подробности — [инженерная проверка](validation-context-optimization.md).

Пакеты закреплены до первого запуска и не менялись:

- AISpa: кандидат после alpha.10,
  [`ba8ce7c3882d13595993ee410981f81196843237`](https://github.com/alexfisenkov/aispa/commit/ba8ce7c3882d13595993ee410981f81196843237).
  Номер пакета остался `0.1.0-alpha.10`; это Git-кандидат, не новый Release.
- Референс: Autopilot 2.1.0,
  [`9fc898cbe941d5b8a369f1dd657e9119676eb44f`](https://github.com/nick-vels/skills/tree/9fc898cbe941d5b8a369f1dd657e9119676eb44f/skills/autopilot).

Проекты: повтор прежней CSV→JSON утилиты, новый HTTP API закладок с SQLite
и доработка существующей библиотеки запасов. Два новых задания и проверочные
наборы подготовлены независимо от навыков и прежних продуктов.

## Условия и единица сравнения

Один Mac, native Codex, Python 3.11/3.14; внешняя приёмка — Python 3.11.15.
Каждая пара начинала с одинакового Git-дерева, имела отдельные каталоги
продукта, навыка и памяти. Все оркестраторы и потомки использовали
`gpt-6.1-sol/high`, свежий контекст и максимум двух одновременно активных
детей. Лимит — 3600 секунд на всё дерево, включая проверки и ожидания.
Участники работали самостоятельно: AISpa auto/balanced, референс full/normal.
Референсу не навязывались дополнительные этапы AISpa.

Порядок до запуска закрепил seed `4952874135884994514`:
CSV AISpa→референс; HTTP референс→AISpa; библиотека AISpa→референс.
Каждый результат заморожен до внешних проверок. После раскрытия проверок
продукты не ремонтировались; неудачные и частичные результаты сохранены.

Первичная единица — проект и обязательные группы R1–R7, не количество тестов.
После автоматических наборов два свежих рецензента на каждую пару проверяли
X/Y в противоположном порядке, без названий методов, истории и метрик.
Из трёх слепых копий README убран только служебный YAML AISpa; исходники
сохранены, преобразования и SHA записаны. Координатор знал соответствие X/Y.
Новые находки воспроизводились одинаково на обеих неизменных версиях.

## Внешняя приёмка

| Проект | Заранее закреплённый основной набор | AISpa | Референс |
| --- | --- | --- | --- |
| CSV→JSON | 61/61 у обоих | **FAIL R5/R6** | **PASS** |
| HTTP + SQLite | 22/22 у обоих | **FAIL R5** | **PASS** |
| Существующая библиотека | 23/23 у обоих | **PASS** | **PASS, замечание к README** |

Собственные тесты из точных чистых Git-клонов прошли:
CSV 19/6, HTTP 14/9, библиотека 33/16 — AISpa/референс.
Группировка тестов различается; эти числа не являются рейтингом покрытия.
После проверок отслеживаемые файлы не изменились, рабочие деревья чистые.

Подтверждённые находки:

1. **CSV AISpa, R6 — заранее закреплённый дополнительный сценарий.**
   При обычном stdout-файле и отказе записи (`RLIMIT_FSIZE=0`, `SIGXFSZ`
   игнорируется только в дочернем процессе) команда возвращает 120 и печатает
   ошибку завершения интерпретатора. Бриф требует 2 и короткую ошибку без
   traceback. Референс возвращает 2 и одну строку ошибки. Оба слепых рецензента
   независимо подтвердили результат во втором адресном круге.
2. **CSV AISpa, R5 — находка после основного набора.** Уже существующее
   записываемое имя выходного файла из 250 ASCII-символов допустимо на
   файловой системе. AISpa включает полное имя в префикс временного файла,
   превышает системный предел и отказывает. Референс пишет отчёт успешно.
   Старые байты у AISpa сохраняются; это отказ поддерживаемого вывода,
   а не доказанная потеря данных.
3. **HTTP AISpa, R5 — находка после основного набора.**
   На `GET /health HTTP/9.9` выдаётся голый JSON без строки HTTP-статуса и
   Content-Type. Референс возвращает оформленный JSON-ответ. Поддержка
   HTTP/9.9 не требовалась: нарушено отдельное безусловное требование
   Content-Type для всех ответов, кроме 204. Два рецензента, воспроизведение
   координатора и отдельный методический разбор подтвердили этот узкий
   дефект границы протокола. Нормальные API-сценарии прошли у обоих.
4. **Библиотека референса — замечание к документации.** README повторяет
   противоречивую фразу исходного задания, будто `2`, `2.5`, `2.500` все
   превращаются в `2.50`. Реальный правильный результат для `2` — `2.00`.
   Один рецензент поставил R7 PARTIAL. Методический разбор сохранил это
   наблюдение как неблокирующий WARN: противоречие пришло из фикстуры,
   а сохранение числового значения соответствует исходному legacy API.
   Оно не используется само по себе для провала одной ветви. Документация
   референса не объявляется безупречной; AISpa явно объяснил выбранное
   толкование. Оригинальный бриф не переписывался.

Прежние 61/22/23 проверки не расширялись задним числом. Дополнительный
stdout-сценарий был закреплён заранее отдельно от 61; длинное имя и
некорректная версия HTTP помечены как находки после основного набора.

потомков, включая финальные ответы. Это не оценка по символам.

native usage не является счётом провайдера. Общая подготовка, координация
эксперимента и внешняя оценка исключены из обоих плеч; они не считаются
бесплатными и не измерены здесь как отдельный полный бюджет.

контрпримеров; первичные отчёты сохранены.

У AISpa отмечены понятное разделение HTTP-кода, потоковое чтение CSV и

Расход RAM и пределы размера входа экспериментально не сравнивались.
Субъективные оценки не отменяют воспроизведённый обязательный дефект.

## Что произошло внутри AISpa

Фактические разные native IDs исполнителя, critic1, critic2 и приёмщика
задачи подтверждены во всех трёх прогонах. Для библиотеки первый критик нашёл
ошибочный номер строки при повреждённом UTF-8; исполнитель зафиксировал
RED, исправил дефект, второй критик перепроверил, отдельный приёмщик принял.
Для CSV и HTTP оба круга прошли без замечаний, но внешняя оценка затем
нашла пропущенные дефекты.

| Проект | Статус движка | Финальный ответ участника | Полнота процесса |
| --- | --- | --- | --- |
| CSV AISpa | accepted | completed | Не зарегистрированы некоторые подготовительные фазы |
| HTTP AISpa | blocked | partial | Финальный пункт о времени заблокирован; knowledge/finish не выполнены |
| Библиотека AISpa | accepted | partial | План составлен координатором, регистрация planner отсутствует |
| Все три референса | final stage done | completed | Противоречий в адресной проверке не найдено; исчерпывающая сертификация всех инструкций не проводилась |

У HTTP-проекта замороженное слепое наблюдение сохранило `not_tested` для
срока до ещё не наступившей финальной передачи. Фактический прогон завершился
за 2256 секунд, раньше лимита. Это блокировка завершения процесса, а не
таймаут и не сама по себе ошибка API; её исходный статус сохранён.

Инструкции требуют регистрации общих фаз. Пробел planner — неполный
локальный учёт роли, а не доказательство отсутствующих внешних токенов.
Отдельный свежий независимый человек для planner текстом однозначно не
требуется: нельзя придумывать дополнительные невыполненные вызовы.
Группировка подготовки ограничивает вывод о полном следовании навыку.

Независимый аудит заново воспроизвёл все **51 участника и 1588 ответов**,
модели, ancestry, суммы, временные границы и хеши. Числовых исправлений нет.
Вердикт: измерение PASS, методика/полнота процесса WARN.

## Повтор прежнего задания и границы экономии

| CSV→JSON | AISpa раньше | AISpa теперь | Референс раньше | Референс теперь |
| --- | ---: | ---: | ---: | ---: |
| Время | 46:13 | 36:30 | 29:14 | 18:25 |
| Вход вне кэша | 1 356 608 | 1 036 188 | 339 738 | 225 874 |
| Выход | 167 828 | 140 363 | 81 507 | 57 919 |
| Проверка отказа stdout | PASS | FAIL | FAIL | PASS |

У AISpa время уменьшилось на 21,0%, вход вне кэша — на 23,6%, выход — на
16,4%. Однако новый продукт не прошёл обязательную приёмку. Эти числа
нельзя объявлять подтверждённой экономией на равном качестве.

Реальное использование новых механизмов подтверждено: в трёх прогонах
сохранены 58/48/53 полных CLI-ответа для compact и 5/4/6 заготовок отчётов.
Это количество артефактов, не пересчёт файлов в токены.
Не отделены причинные вклады compact, форм, объединения задач, регистрации
фаз, кэша и вариативности модели. У обеих ветвей появился одинаковый
помощник определения native identity вместо сообщений координатора.
Референс при повторе также ускорился. Прежний опыт —
[отдельный отчёт](validation-alpha.10-paired-test.md).

## Ограничения и следующий цикл

- Один запуск на метод/проект, три небольшие задачи; статистической
  значимости и обобщения на большие проекты нет. CSV — повтор, два других
  задания новые. Проверены Codex/macOS; native Claude Code/Cursor и
  модельные прогоны на Windows этим опытом не покрыты.
- Изоляция — отдельные каталоги и инструкции, не виртуальные машины.
  Жёсткая частота контроля координатором раз в 60 секунд не подтверждена:
  были более длинные интервалы. Все ветви завершились до лимита;
  отбрасывания позднего usage не было. Остановку по таймауту под нагрузкой
  этот опыт не доказывает.
- Полнота относится к выданной и сохранённой телеметрии. Невидимые запросы
  без usage не восстанавливаются; связывание финального сообщения и
  response ID опирается на порядок событий хоста. Начальный интервал
  dispatch→native start не называется доказанным ожиданием провайдера.
- Новые oracle прошли негативные контроли, но при подготовке не создавалась
  полная эталонная положительная реализация. Неоднозначность цены сохранена
  и разобрана одинаково для обеих ветвей. Основные наборы не исправлялись.

Следующая работа: убрать зависимость приёмки от будущего финального события,
замкнуть учёт подготовительных фаз без лишних участников, сократить
повторяющиеся согласования малых задач и усилить проверку реальных
I/O-отказов и протокольных ошибок. Два критика и отдельный приёмщик остаются.
Измеренные продукты не чинить: следующий кандидат проверять на новом
заранее закреплённом наборе, чтобы не обучаться только на известных тестах.
Публикация нового Release в этой итерации не выполнялась.

## Свидетельства

- [Числовые метрики](pilots/context-optimization/paired-test/metrics.json):
  все входные/cached/uncached/output/reasoning значения, точное время,
  commits и хеши сохранённого usage.
- [Приёмка и оценки](pilots/context-optimization/paired-test/acceptance.json):
  отдельные статусы продукта/движка/ответа, находки и оценки двух рецензентов.
- [Инженерные проверки](pilots/context-optimization/engineering.json).

Полные native-логи, исходные ответы, bundle и tar точных commits, отдельные
снимки рабочих каталогов, контрольные суммы и отчёты рецензентов сохранены
в приватном игнорируемом архиве. В публичную историю не включены личные пути,
native IDs и чужой пакет навыка. Public metrics
`measurement_contract_checks_passed` означает проверки измерителя;
это не общий PASS продукта или процесса.
