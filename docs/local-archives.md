# Локальный архив AISpa

После уборки 23.10.2026 рабочий репозиторий содержит исходники, тесты и публичные
документы. Старые `.проверки/`, `.источники/` и `документы/` сохранены в локальном
архиве `.архив/2026-10-23-порядок/`, исключённом из Git. В GitHub его нет.
Исторические текстовые ссылки на эти каталоги обозначают путь **внутри снимка**.

## Что сохранено

- `aispa-before-cleanup.tar.gz` — дерево проекта до уборки, включая `.git`,
  семь дополнительных worktrees, 70 вложенных тестовых Git-репозиториев,
  их локальные изменения, исходные исследования и журналы.
- `archive-manifest.json` — список членов архива, размеры и SHA-256 файлов.
  Проверены все 18575 обычных файлов; всего 22269 членов.
- `aispa-before.bundle` — отдельная Git-история со всеми исходными refs.
- `git-before.json`, `local-cleanup.json`, `branch-cleanup.json` — исходные
  ссылки и выполненная уборка.
- `github-releases-before.json`, `github-pulls-before.json` — резервные копии
  публичных описаний перед исправлением устаревших статусов/ссылок.

База Git: `158377bb353093d1cd404742487a6f94f68c5558`. Снимок также содержит добавленное перед
архивированием правило `.архив/` в `.gitignore`. Архив находится на том же Mac;
это возможность отката уборки, а не независимая внешняя резервная копия.

SHA-256 архива: `6aa1185eb6b744d73118b3f2e53765df6c18b56dda1d78dafd7984ad75ac7451`.

## Найти старое свидетельство

Из корня AISpa можно читать архив без распаковки:

```bash
tar -tzf .архив/2026-10-23-порядок/aispa-before-cleanup.tar.gz
```

Например, исходный локальный аудит:

```bash
tar -xOf .архив/2026-10-23-порядок/aispa-before-cleanup.tar.gz документы/АУДИТ-БРИФА.md
```

Для восстановления Git используйте bundle и **новую свободную папку**:

```bash
git clone .архив/2026-10-23-порядок/aispa-before.bundle /путь/к/новой-папке
```

Локальные незакоммиченные материалы берутся из tar-снимка, не из bundle.
Полный tar нельзя распаковывать поверх рабочего проекта: в нём находятся старые
`.git` и указатели worktrees с прежними путями. Извлекайте нужные файлы отдельно;
регистрацию рабочих деревьев при необходимости создавайте из сохранённых refs.
