# Проверка условной критики и исправлений приёмки

Изменения относятся к Git-кандидату после alpha.10. Опубликованный Release
и активные закреплённые прогоны не заменяются. План —
[plan-adaptive-review.md](plan-adaptive-review.md).

## Что изменено

- Первый явный PASS ведёт к отдельному приёмщику. WARN/BLOCK/FAIL требуют
  действительного ремонта, затем нового критика. Максимум два раунда.
- Подготовительная фаза ссылается на реального автора и неизменный отчёт;
  один координатор может вести несколько авторских фаз без выдуманных агентов.
- При одной задаче в одной волне полная независимая финальная приёмка может
  подтвердить последнюю сверку волны при совпадении всех доказательств.
- Заранее зарегистрированный срок движка проверяется по фактическому finish;
  будущий host-final-handoff сохраняется как pending, а не продуктовый FAIL
  или выдуманный PASS. Исходное blind-наблюдение остаётся неизменным.
- Исторические сроки сохраняют исход и происхождение. Новое решение владельца
  может снять обязательство, но не переписать pending/failed в passed.
- Отказные границы включены в test-intent и проверки критика/приёмщика.
  Изменение источника после приёмки делает доказательство задачи устаревшим,
  включая игнорируемый Git файл. Изменённый при ремонте источник допустим
  только в точном состоянии, рассмотренном приёмщиком.

## Независимая критика

Первый круг обнаружил несвязанность типа события/срока со смыслом источника,
раннее назначение critic2 и необработанный тип event. Добавлены два независимых
исходных прочтения срока, машинные проверки буквальных событий/ISO-времени,
контроль действительного ремонта перед назначением и проверка типов.

Второй круг выявил ложный отказ относительного бюджета с явно указанным
началом, повторное использование одинаковых слов владельца для смены решения
по одному историческому обязательству и устаревание тестовых источников вне
обычного снимка кода. Исправления покрыты отдельными регрессиями. Один новый
бриф может адресно разрешить несколько разных исторических обязательств;
новый номер B-ID с теми же словами не даёт нового решения по одному CE.

## Проверки

Первый общий локальный набор: 622 теста, 602 PASS и 20 OS-specific SKIP,
277.524 с. Финальный повтор после исправлений на macOS/Python 3.14:
629 тестов, 609 PASS и 20 OS-specific SKIP, 253.260 с. Node — 37/37,
пример study-plan — 15/15. Проверены 176 локальных Markdown-ссылок без
пропавших целей; скан изменённых файлов не обнаружил шаблонов секретов
и локальных домашних путей. Это ограниченная автоматическая проверка.

В реальном браузере на localhost просмотрена синтетическая демонстрация:
ветка первого PASS показывает пропуск ремонта/critic2, ветки ремонта и
повторной проверки сохранены. Демо не является результатом реального агента.

## Границы доказательств

Новая модельная батарея ещё не запущена; экономия времени/токенов не заявляется.
[Финальная CI](https://github.com/alexfisenkov/aispa/actions/runs/39548762214)
для `7b39b9e33e9cf6d09af808f510dd5d6b4d2facec` прошла все шесть jobs:
macOS/Linux — 609 PASS / 20 SKIP, Windows — 628 PASS / 1 SKIP из 629
тестов на каждой версии Python 3.11/3.13. Пример — 15/15 в каждом job;
Node — 37/37 на каждой ОС в job Python 3.13.
[Квитанция CI](pilots/adaptive-review/ci.json). Последующие коммиты
регистрации/результатов меняют документацию, не проверенный пакет.
Claude Code/Cursor и физические компьютеры учеников здесь не испытаны.

Движок сохраняет заявленное авторство, но не удостоверяет личность модели
криптографически. Интерпретация естественного языка остаётся работой независимых
читателей; буквальные guards не заменяют её. Исполнительное обязательство
требует отдельной точной исходной единицы. Поздняя квитанция внешнего host-event
не поддержана; это явное ограничение, а не скрытый успешный статус. Матрица
отказов проверяет полноту ссылок, а не семантическое качество тестов.
