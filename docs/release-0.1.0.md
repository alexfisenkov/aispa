## Два маршрута задач

- `heavy` используется по умолчанию и при неопределённости. Первый PASS критика
  ведёт к отдельному приёмщику; WARN/BLOCK/FAIL требуют ремонта и нового
  critic2. Максимум два круга, без обхода через reset/replan/переименование.
- `light` предназначен для обоснованных низкорисковых, обратимых правок обычной
  документации и оформления в точных безопасных файлах. Логика, данные,
  доступы, зависимости, публичные контракты и правила проекта остаются heavy.
- У light есть настоящий worker, адресная проверка и полный worker-report.
  Успешный submit даёт `verified_completion` без отдельных task critics и
  acceptor. Это подтверждённое выполнение задачи, а не приёмка всего продукта.
- Новый риск фиксируется через `promote-task`: light повышается до heavy,
  прежняя попытка сохраняется, доказательство снимается и проверка начинается
  по тяжёлому маршруту. Понижение после начала работы запрещено.

## Общая проверка и интерфейс

Обзор всей версии обязателен: для финальной heavy он входит в её критику,
для финальной light выполняется отдельно через `integration-review` свежим
независимым участником. Сохраняются пять направлений, полный diff, проверяемые
свидетельства и связь с текущим кодом. Самопроверка worker не заменяет этот обзор.
Далее остаются handoff, чистый клон и отдельная итоговая приёмка по исходному брифу.

Панель показывает класс и обоснование. Light получает подпись «Выполнение
проверено»; смешанная волна — «выполнено и проверено». Это не общий статус
`accepted`. У heavy сохраняются условный второй круг и отдельный приёмщик.

В выпуск также входят изменения после опубликованной alpha.10: формы отчётов
без автоматических оценок, компактные ответы со ссылкой на полный оригинал,
стабильные адреса контекста, учёт подготовительных фаз, сроков исполнения и
отказных проверок. Предыдущие испытания этих изменений остаются историческими.

## Установка и совместимость

Первый установщик по умолчанию выбирает опубликованный stable SemVer с
GitHub `prerelease=false`. Более высокий prerelease не вытесняет stable;
при отсутствии stable выдаётся ошибка. Явный опубликованный `--tag` сохраняет
доступ к prerelease. Фактический булев флаг GitHub показан в preview.

Новая политика включается только новым init. Alpha.10 и её закреплённые runtime
не мигрируют; завершённую историю можно прочитать для handoff. Обновление
установленной папки и откат требуют подтверждения, проверки неизменности
кандидата и сохранённой копии. Глобальная установка не меняется автоматически.

## Границы доказательств

Новых полных модельных прогонов и повторов референса для 0.1.0 нет по решению
владельца. Экономия токенов нового маршрута не измерена. Инженерные проверки,
стабильный номер и публикация не подтверждают все пользовательские сценарии,
работу каждой модели или всех машин учеников. Прежние отчёты alpha и модельные
сравнения не переписаны.
