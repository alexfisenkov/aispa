# Единый справочник: источник, публикация и поддержка

Канон — [support-faq.json](../skills/aispa/references/support-faq.json) внутри
навыка. [Человеческий текст](support-faq.md) создаётся из него детерминированно;
второй редактируемой JSON-копии в docs нет. Selector проверяет schema,
обнаруженную версию пакета, stable entry IDs и SHA каждого указанного источника.
`canonicalSha256` считается по исходным байтам JSON, `sourceSha256` — по карте
источников, `outputSha256` — по результату. SHA самого JSON внутрь него не пишется.

В рабочем дереве разработчика:

```sh
python3 -B tools/render_support_faq.py --package skills/aispa --version <обнаруженная-версия> --format markdown --output docs/support-faq.md --receipt <приватный-файл-квитанции>
```

К тому же вызову добавляют `--check`, чтобы проверить уже созданные байты без
перезаписи. `--format html` даёт видимые Q/A для учебного материала, `--id <ID>`
выбирает конкретные ответы. Generation receipt отдельно сохраняет версию,
точные IDs, source files/SHA и input/output SHA. Видимый текст не содержит
номера версии AISpa. Это authoring tool Git-проекта; в установленном навыке
используется его собственная команда `faq`, а root tools/docs не требуются.

Первая установка или обновление доставляет FAQ вместе с остальными файлами
через проверенный Release manifest и архив. Коммит/manifest/архив связываются
штатным установщиком, а receipt генерации относится к выбранным байтам.
Рабочий кандидат с локальными тестами не становится опубликованным выпуском.
Старый pinned runtime сохраняет прежний контракт: обнаруженная версия берётся
у его CLI; отсутствие FAQ/команды или несовпавшие source SHA — причина остановить
свежую справочную подстановку, а не переписать runtime/журнал.

## Граница реальной учебной интеграции

В этой итерации **внешняя публикация и использование помощником не подтверждены**.
Новые команды кандидата не помещались в действующий урок. Локальный пакетный
consumer и renderer проверяются отдельно от доставки текста на учебные площадки.

Для реального inline-маршрута нужны fresh baseline/CAS и read-back сохранённого
текста в GetCourse, затем поддержанный оркестратором перенос текста/публикация
на собственной платформе и её read-back. Даты, доступ, порядок, видео и домашнее
задание таким изменением не затрагиваются. Generation receipt связывают с
полученными lesson/content hashes и опубликованной ревизией; наличие ссылки
на статью не подтверждает скачивание её содержимого.

Действующий серверный lesson reader передаёт live block text и contentHash.
Скрытые HTML-поля и ссылка сами по себе не создают исторический FAQ selector.
Остаются конкретные внешние блокеры: доверенный подписанный read точного урока,
текущий Windows checkout/поддержанный host route и развёрнутый путь сборки
context/cache помощника не установлены в доступном контуре. Это статус
**UNVERIFIED**, а не доказательство отсутствия или отключения клиента.
Реальные технические адреса и receipts хранятся в приватном контуре школы.

После получения доступа structural fixture должна показать замену cached text
по новому contentHash, попадание точных Q/A в context и приоритет свежего
письменного справочника над старой расшифровкой. Для этого не нужны платный
model call или сообщение ученику; качество естественного ответа проверяется
отдельно. До этих receipts полный R11 live-consumer PASS отсутствует. Новый
серверный fetcher или ещё один FAQ-сервис не устраняет неизвестность Windows
consumer и не добавляется ради обхода блокера.

Публичный FAQ состоит из общих оригинальных ответов. Переписка, идентификаторы
и данные учеников, секреты и приватные receipts не становятся его источниками.
