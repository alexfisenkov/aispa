# Проверки AISpa 0.3.2

[Стабильная v0.3.2 опубликована](https://github.com/alexfisenkov/aispa/releases/tag/v0.3.2)
22.10.2026, 15:30:31 UTC. Source commit —
`8698e979988e76906f48e872c5cfa45f1d1455f8`.
План/причины: [plan-live-dashboard-autonomy.md](plan-live-dashboard-autonomy.md).

## Подтверждённый реальный отказ

Read-only вызов status закреплённой 0.3.0 дал TypeError в round(value,3):
после двух completed ETA получила pending.elapsedSeconds=null. Это остановило
весь status, хотя событие сдачи задачи уже было записано. Повторять мутацию по
одной ошибке представления нельзя. Журнал работающего проекта не правился.

## Границы

Новые вопросы не обходят ни ограничения host, ни отсутствие полномочий.
Изменение файла само по себе не означает реализации/приёмки требования.
Время без наблюдений — широкий ориентир по плану, не измеренная длительность.
Read-only viewer старого прогона не исправляет его старый CLI и не меняет policy.
Фактические тесты, UI и доставка записываются ниже по мере выполнения.

## Локальная проверка

Первый общий набор: 254 Python-теста, 253 PASS и один HTTP409 при одновременной
записи журнала. Корень воспроизвёл гонку курсора; обработчик теперь до трёх раз
создаёт свежего reader только для штатного append. Повреждение по-прежнему 409.
Три детерминированные регрессии и исходный тест writer-lock после исправления
PASS (исходный — 5.007 с). 26 тестов timing/display-details после замечаний
PASS. 64 Node-теста панели PASS. [Квитанция](pilots/0.3.2/local-verification.json).

Пакеты, карточки, CLI и memory проверены по новым autonomy-тестам и существующим
целевым наборам. Синтетический HTTP воспроизвёл две completed + running +
pending null: ответ остаётся JSON200. Совместимый refresh-view проверен с
побайтно неизменными journal/active/pinned; вывод версии viewer отделён от run.
Code cache в одном запросе дал 6 → 2 вызова Git на трёх одинаковых запросах,
с теми же хешами; реальное ускорение пользовательского проекта не измерялось.

## UI и независимая критика

Видимый IAB: фактическая CSS-ширина 1600 и 390 пикселей, требования T03 раскрыты
нативным нажатием. Browser viewport override и измерение innerWidth различались
из-за масштаба браузера: сохранены оба значения в viewport-measurements.json.
Временный viewport сброшен. [Финальный широкий экран](pilots/0.3.2/final-wide-full.png),
[финальный узкий экран](pilots/0.3.2/final-narrow-full.png),
[раскрытый AX](pilots/0.3.2/final-narrow-expanded.txt).
Предыдущие PNG сохранены как ранние наблюдения, не как финальная вёрстка.
Это синтетические данные, а не проверка качества готового пользовательского продукта.

Техника, круг 1: скорость лёгких задач переносилась на тяжёлые, предварительный
worker-report выглядел окончательным PASS, историческая сверка волны не была
подписана. Исправлено: наблюдения строго своего класса; reported/provisional
с отдельной подписью; нейтральная историческая метка. Круг 2: OK по изменённому
периметру и новой узкой обработке гонки. Критик не запускал тесты сам.

Команды/exit codes и выводы: [test-commands.json](pilots/0.3.2/test-commands.json).
[Повтор реального отказа](pilots/0.3.2/old-status-error.json) обезличен;
[refresh-view до/после](pilots/0.3.2/refresh-view-verification.json) сохраняет
SHA journal/active/pinned и сырой JSON ответа. Доставка описана ниже.

Проверка доказательств: закрыты финальные expanded-снимки, сырые команды/логи
и SHA до/после refresh-view. После второго круга основной агент добавил
версию старого runtime через --version и явно разделил SHA исходного и
обезличенного лога. Третьего круга нет; финальная metadata-сверка — основным агентом.

## Финальная CI и адресное уточнение теста

[Первый запуск](https://github.com/alexfisenkov/aispa/actions/runs/39804132915)
проверяет 258 тестов. Ubuntu выявила одно устаревшее ожидание в
`test_live_projection_includes_blockers_before_final_delivery`: тест ожидал
reason=blocked, хотя новый согласованный экран возвращает условное рабочее
время с waitingForBlockers=true и waitIncluded=false. Проверка сохранности
блокера остаётся; обновляется только ожидание ETA. Production-код не меняется.
Адресный повтор dashboard-fix проверяет этот тест, timing и UI на трёх ОС;
полные модельные прогоны и повтор всего Python-набора не запускаются.

## Публикация и установка

[Ресурсы](https://github.com/alexfisenkov/aispa/actions/runs/39805488343) — PASS;
три скачанных файла совпали побайтно с воспроизводимой сборкой точного SHA,
пакет содержит 89 файлов. [Квитанция](pilots/0.3.2/release-verification.json).
Production-пакет совпадает с первым CI commit fbc0cda: между ним и тегом
изменены тест, workflow и документы, а не runtime/HTML.

Все четыре локальные установки обновлены 0.3.1 → 0.3.2 через prepare/apply;
SHA, размеры и режимы всех файлов совпали, backups проверены. Общую копию
используют Codex/OpenClaw/Gemini, остальные — Claude Code, Cursor, Antigravity.
После публикации один update-check временно дал no_release; повторная живая
проверка всех четырёх вернула current. [Проверка](pilots/0.3.2/installation-verification.json).
Нативные GUI-каталоги всех приложений повторно не проверялись.

## Финальные CI-границы

В первом CI все шесть jobs выполнили 258 тестов: единственный отказ в каждой —
описанное выше старое ожидание blocked вместо условной ETA. После исправления
[адресная матрица](https://github.com/alexfisenkov/aispa/actions/runs/39805156332)
дала success во всех шести jobs: startup-smoke, 17 Python-проверок и 64 Node
на трёх строках Python3.13. Полная Python-матрица повторно не запускалась.
На последнем read-back агрегированный статус run ещё был in_progress,
хотя все jobs completed/success; это не объявляется завершённым aggregate-run.

## Панель действующего проекта

Из опубликованной установки выполнен refresh-view по прежнему loopback-порту.
Журнал 0.3.0, active.json и всё дерево pinned runtime остались побайтно
неизменными. Показаны viewer 0.3.2 / проект 0.3.0; нативный IAB прочитал живые
завершённые/текущие задачи и численную ETA. [Обезличенная квитанция](pilots/0.3.2/active-view-verification.json).
Сырые скриншоты/AX действующего проекта остались приватными; публичные снимки
выше — только синтетические. Новый viewer исправляет панель, но не переписывает
старый CLI: начатая разработка продолжает прежний runtime. Новая жёсткая граница
вопросов действует в новых init; старую policy не мигрировали.
