# Лёгкие и тяжёлые задачи · выпуск 0.1.0

Решение владельца 21.10.2026: внедрить два маршрута, сохранить общую приёмку
по брифу, не выполнять новые полные модельные прогоны. После инженерных
проверок разрешён опубликованный Release 0.1.0 без alpha и prerelease.
Статус: SHIPPED — [выпуск и проверка доставки](validation-0.1.0.md). Номер остаётся 0.x; переход к 1.0 не запрошен.

## Контракт

Класс задаётся до исполнения и сохраняется в плане, карточке и истории
попытки. По умолчанию и при неопределённости — heavy. risk=low сам по себе
не выключает критиков. Light требует предметного обоснования, низкого риска,
ограниченной зоны и поддерживаемого вида обратимого изменения. Изменения
логики, данных, доступов, зависимостей, публичных контрактов и правил проекта
относятся к heavy. Короткий diff и расширение файла не доказывают безопасность.

Light: настоящий исполнитель → актуальная адресная проверка → worker-report
с доказательствами → verified completion. Отдельных critic1/critic2 и
приёмщика каждой такой задачи нет; фиктивный PASS не создаётся. Это ещё
не приёмка всего продукта. Heavy сохраняет первый PASS → отдельный приёмщик;
non-PASS → ремонт → свежий второй критик → приёмщик, максимум два круга.

При новых рисках доступно явное повышение класса с сохранением истории и
инвалидацией прежнего доказательства. Понижение после начала работы либо
через reset/replan/переименование не обходит использованные проверки.

Независимый обзор всей версии остаётся обязательным. Если финальная задача
heavy, он входит в её штатную критику. Если light — отдельный общий отчёт
независимого участника перед handoff/clean clone. Это один обзор проекта,
а не отдельный критик каждой лёгкой задачи. Сохраняются пять осей, полный
список изменений, свежесть кода и доказательств. Затем — чистый клон,
независимая сверка исходного брифа и итоговая приёмка. Worker не подписывает
общую независимую проверку собственного кода.

Новая политика включается в новых init. Старые журналы, digest и закреплённые
runtime не мигрируют автоматически. Alpha.10 остаётся читаемой историей.

## Реализация и проверка

1. Движок, защищённые переходы и доказательства light/heavy; шаблоны и оценки ролей.
2. Отображение класса и фактического маршрута в панели без ложного accepted.
3. Инструкции, стабильная версия 0.1.0, установка по умолчанию из stable Release,
   совместимость alpha.10 → 0.1.0 → rollback в изолированных каталогах.
4. Адресные регрессии, независимая критика; второй круг по замечаниям, максимум два.
5. Один полный локальный набор и одна финальная CI на трёх ОС для release commit.
6. Tag v0.1.0 и публичный Release prerelease=false; штатная сборка трёх ресурсов,
   скачивание и сверка с воспроизводимой сборкой, изолированная установка/обновление.

Новых полных модельных испытаний и повторов референса — ноль. Экономия токенов
нового маршрута не измеряется и не объявляется. Инженерные проверки и выпуск
не равны подтверждению всех сценариев поведения моделей или всех машин учеников.

## Основание предыдущего исследования

В закреплённых инструкциях референса 2.1.0 (9fc898cbe941d5b8a369f1dd657e9119676eb44f,
phases/4-plan.md и phases/6-review.md) большинство обычных задач обходится без
точечного ревью, сохраняя общий обзор и финальную приёмку. Это факт чтения
инструкций, не новый запуск. Чужие исходники и формулировки в AISpa не копируются.
