# Выпуск AISpa 1.0.0: шаги после «да» владельца

Это протокол, а не отчёт: здесь ничего не выполнено. Каждый шаг ниже делается
только после отдельного «да» владельца на выпуск. Одобрение сборки, проверок
или этого файла таким «да» не считается.

## До «да»

Сборка закончена и принята; по ходу работы гонялись только тесты затронутых
мест. Полный набор тестов прогнан один раз на итоговой версии
(`python3 tools/check.py`), слепая приёмка по брифу и замер сделаны. Владелец
видел итог и сказал «да» именно на выпуск.

## Шаги после «да»

1. **Тег пути отката в GitHub.** Тег `aispa-0.5.0-engine` должен быть в
   GitHub: на нём и на `v0.4.0` стоят проверки совместимости и откат. Нет его
   там — отправить сам тег, ничего больше.
2. **Один итоговый CI.** Вручную запустить `.github/workflows/checks.yml`
   (область `full`) на итоговом commit ветки — один раз, без повторов без
   новой причины. Если бюджет GitHub Actions исчерпан, выпуск идёт по правилу
   владельца для выпуска без CI: локальные проверки по точному SHA, сборка
   из него и проверка результата чтением; в отчёте так и написать — «CI не
   запускался».
3. **Слияние в `main`.** Ветку сборки слить в `main` одним заходом; commit
   `main` после слияния — тот, что прошёл шаг 2 (или повторить шаг 2 на нём,
   если слияние дало новый commit с другим деревом).
4. **Тег `v1.0.0`** на этом commit. Версия в `tools/aispa_core/__init__.py`
   и `metadata.version` в `SKILL.md` — `1.0.0`; иначе сборка выпуска откажет.
5. **Release.** Опубликовать Release `v1.0.0` (стабильный: не черновик, не
   prerelease). Файлы `aispa.zip`, `aispa-update.json` и `install.py`
   прикрепляет `.github/workflows/release.yml`; перечитать, что все три на
   месте, по одному и в состоянии `uploaded`.
6. **Проверка доставки.** Во временной папке: `install.py preview --tag v1.0.0`
   и `apply` — установка проходит, для Claude Code рядом встают шесть агентов.
   Установка прежней версии видит `1.0.0` в `update-check`.
7. **Установки владельца.** Каждую его установку обновить отдельно фразой
   «обнови AISpa»: проверка, кандидат, его «да», резервная копия. Сохранить
   `backupId` каждой.
8. **Флаг автозапуска в копиях владельца.** В пакете у `SKILL.md` остаётся
   `disable-model-invocation: true` — у учеников AISpa сама не запускается.
   В личных копиях владельца флаг снимается снова, по его правилу
   оркестрации: там модель запускает AISpa сама. Обновление ставит пакет
   с флагом, поэтому этот шаг повторяется после каждого обновления его копий.
9. **Правило оркестрации владельца.** Оркестратор обновляет раздел AISpa в
   этом правиле под 1.0: что это за версия, как она запускается и чем
   проверяется. Это собственные файлы правил владельца.

## Откат

Путь отката — теги `v0.4.0` и `aispa-0.5.0-engine` и резервные копии каждой
обновлённой установки (`update-rollback --backup <backupId> --confirm`).
Удалять что-либо из `main` до приёмки владельцем нельзя.
