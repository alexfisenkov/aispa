# Проверка оптимизации служебного контекста

Исторический протокол кандидата от 21.10.2026. Последующие изменения вошли
в [стабильную 0.1.0](validation-0.1.0.md); [текущий статус](status.md)
ведётся отдельно. Старые числа и ограничения этого измерения сохраняются.

21.10.2026. Кандидат после alpha.10; новый Release ещё не опубликован.

Изменения:

- `template worker|critic1|critic2|acceptor --task … [--write]` вычисляет
  служебные поля. Оценки, независимость и evidence остаются незаполненными;
  заготовка не проходит действующую приёмку.
- `--compact` перед обычной командой записи или `status` сохраняет полный
  JSON и возвращает короткий ответ с адресом и SHA. При недоступном архиве
  выводится полный результат, исходный код выхода сохраняется; выполненная
  запись не выдаётся за отменённую.
- Одинаковые разделы context повторно используют адрес SHA. Изменение
  содержимого создаёт другой адрес; повреждение не перезаписывается.
- Финальный порядок commit → verify → handoff → wave → clean позволяет
  не повторять ревью волны только из-за лишнего запуска той же общей проверки.
- Логотип, «AI мастерская» и AISpa открывают публичный канал мастерской.

## Два круга независимой критики

Технический критик и критик доказательств в первом круге указали:

1. `template --write` считался чтением и обходил проверку pinned runtime /
   незавершённого восстановления журнала.
2. Ошибка сохранения compact после записи действия могла дать ложный общий
   отказ без результата и спровоцировать повтор команды.

Исправления: запись черновика проходит обычные write-gates; ошибка compact
возвращает полный исходный JSON и предупреждение. Настоящие CLI-регрессии
подтверждают оба ограничения и однократность записи решения.
Оба критика дали **OK во втором адресном круге**. Их выводы по коду и
сохранённым логам не заменяют runtime, CI или модельное испытание.

При первом запуске новых регрессий один assert неверно читал поле
`decisions` вместо канонического `notes`; исправлен именно тест.
История ошибки сохранена. Исправленный адресный набор — **12/12 PASS**,
после него выполнен полный набор выше.

## GitHub Actions и модельное испытание

Первая CI `39461530565` обнаружила в Windows 3.11/3.13 ошибку нового тестового
вызова: один аргумент `decision` превышал лимит Windows CreateProcess
(`WinError 206`), поэтому CLI не запускался. Объём тестового текста уменьшен
в пределах системного лимита; полный ответ по-прежнему больше 10 000 байт,
краткий меньше 4096, а содержимое восстанавливается полностью. Это правка
фикстуры, код навыка не меняется.

Повторная [финальная CI](https://github.com/alexfisenkov/aispa/actions/runs/39464558131)
для `ba8ce7c3882d13595993ee410981f81196843237` — **все шесть jobs PASS**:
547 Python-тестов на job, Windows 546 PASS / 1 OS-specific SKIP,
macOS/Linux 527 PASS / 20 OS-specific SKIP. Пример — 15/15 во всех jobs;
Node — 36/36 на каждой ОС в job Python 3.13.
[Машиночитаемое свидетельство](pilots/context-optimization/engineering.json).

Mac-батарея начата параллельно повторной CI после проверки, что Git tree
`skills/aispa` совпадает с уже проверенным на macOS/Linux первым кандидатом;
исправлялась только тестовая фикстура. До завершения новой матрицы готовность
Windows не заявлялась. Сам пакет в ходе модельных запусков не меняется.
