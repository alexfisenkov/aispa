# Условная критика, приёмка и учёт фаз

Решение владельца 21.10.2026: после PASS первого критика задача переходит
к отдельному приёмщику. WARN/BLOCK/FAIL требуют исправления и второго свежего
независимого критика. Второй non-PASS или отказ приёмщика завершает попытку
блокировкой; скрытых третьих кругов и обходов через reset нет.

Исходные проблемы и измерения: [предыдущее испытание](validation-context-optimization-paired-test.md).
Исторические результаты и замороженные продукты не изменяются.

## План

1. Единая проверка допустимой цепочки: новый первый PASS без фиктивного critic2;
   обязательный repair и critic2 после non-PASS; те же правила в исторических
   доказательствах, интеграции, шаблонах и панели. Явные вердикты согласованы
   с проверками и находками. Новые политики включаются только в новых прогонах;
   отсутствие политики сохраняет прежний контракт.
2. Разделить продуктовую приёмку и узкие заранее зарегистрированные обязательства
   исполнения. Нельзя удалять исходное blind-наблюдение, переносить продуктовый
   core в исключение или выдавать будущую передачу за уже выполненную.
   Будущее событие остаётся явным остатком; событие движка проверяется по его
   действительной временной отметке.
3. Связать фазу с действительным автором и неизменным отчётом. Координатор
   может выполнять авторские фазы без выдуманного второго участника;
   независимые проверки не получают такого исключения. Usage считается один
   раз по реальным вызовам, пробелы авторства видны отдельно.
4. Для одной задачи/одной волны независимая финальная приёмка может покрыть
   последнюю сверку волны при точном совпадении кода, scope и доказательств.
   Промежуточные волны и отдельная source-only финальная проверка сохраняются.
5. Усилить планирование и проверку отказов: явные применимые границы, настоящие
   отказы ввода/вывода/хранилища/протокола, проверка сохранности при отказе.
   Не требовать неподдерживаемого поведения вне исходного контракта.
6. Целевые проверки, независимая критика изменений и адресный второй круг
   только по находкам; полный локальный набор, GitHub и финальная CI трёх ОС.
7. До запуска закрепить три новых задания, скрытые проверки, версии, порядок,
   модель и лимиты. По одной изолированной попытке каждого навыка на проект;
   референс не получает наших правил критики. Полный native usage всех потомков.
8. Заморозка продуктов, одинаковая внешняя приёмка чистых клонов, слепое ревью,
   независимая проверка измерений и публичный отчёт с неудачами и ограничениями.

## Границы

Модель сравнения — выбранная владельцем `gpt-6.1-sol/high` для обеих ветвей.
Известные задания прошлого опыта не служат новой скрытой оценкой. Новый Release
и глобальная установка в этом поручении не запрошены. Улучшение скорости не
объявляется улучшением продуктивности при ухудшении обязательного результата.

## Статус

Реализация, два круга инженерной критики и итоговые локальные проверки
выполнены; финальная CI всех трёх ОС и обеих версий Python прошла. Новые задания подготовлены независимо; модельная
батарея ещё не запускалась. [Свидетельства](validation-adaptive-review.md).
