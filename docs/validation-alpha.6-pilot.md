# Нативный пилот AISpa alpha.6 · 19–20.10.2026

Пилот завершился статусом `accepted`: две задачи, две волны и восемь обязательных
требований. Испытан опубликованный пакет `0.1.0-alpha.6` из commit
`2f2d1eb5184f3aae629f5d074bae6275072f6679`, без изменения его кода во время прогона.
Среда модельного исполнения — Codex на macOS, роли — `gpt-6-sol`.

Продукт — [«Учебный план»](../examples/study-plan/README.md): локальная программа
выбирает CSV-задачи по приоритету и бюджету времени, выдаёт JSON и сохраняет
файлы при ошибках. Бриф синтетический: координатор выбрал пример по поручению
владельца. В нём нет данных учеников, сети, аккаунтов или внешних зависимостей.

## Измерение контекста

Проверялось восстановление рабочего контекста после первой волны. Это один
замороженный snapshot: во всех вариантах одинаковый полный бриф, требования,
спецификация, текущий план, правила и доменный код — 26 475 общих байт.

- **A:** все проектные документы и логическая история отчётов. Источники
  перечислены один раз, без повторяющихся снимков `events.jsonl`.
- **B:** настоящий каталог AISpa, выбранные документы для следующего шага и
  та же история.
- **C:** тот же каталог и выбранные документы, штатные memory/decisions и
  последнее принятое доказательство T01 вместо полной истории.

Каждый вариант выполнен дважды свежей моделью `gpt-6-sol`, effort `medium`.
В каждом запуске одинаковые пять чтений и шесть модельных запросов. Все 30
прочитанных частей сверены по хешам; все шесть ответов содержат 12/12 верных
фактов, включая следующую задачу и сохранённое необязательное замечание.

Счётчики взяты из настоящих native `token_usage_record`, по уникальным response ID.
Накопительные счётчики повторно не складывались; независимая проверка воспроизвела
суммы по исходным журналам. Ни байты, ни символы не переводились в условные токены.

| Среднее двух запусков | A: полное чтение | B: каталог и выбор | C: каталог, выбор и память |
|---|---:|---:|---:|
| Вход запроса после полного чтения, токены | 70 815 | 73 465 | 67 704 |
| Изменение относительно A | — | +3,742% | −4,393% |
| Суммарный input шести запросов | 374 794,5 | 383 024 | 365 671 |
| Изменение суммарного input | — | +2,196% | −2,434% |
| Переданные материалы, байты | 74 573 | 80 438 | 54 785 |
| Правильные факты за два повтора | 24/24 | 24/24 | 24/24 |

**На этом проекте каталог сам увеличил контекст.** Он добавил 11 933 байта,
а отбор исключил только 6 068 байт документов. Замена истории памятью убрала
ещё 25 653 байта: общий объём материалов уменьшился на 26,535%, но реальный
вход модели после чтения — только на 4,393%. Начальный служебный контекст среды
составлял около 54 тысяч токенов на свежего агента и заметно уменьшал общий эффект.

Cached input входит в input и не прибавляется к нему. Его различия не используются
для обещания денежной экономии. Output уже включает reasoning. Полные числа по
шести запускам, кешу и выходу: [context-metrics.json](pilots/alpha.6/context-metrics.json).

Первые пять калибровочных запусков с большим одноразовым выводом не обеспечили
надёжную доставку полного текста модели и исключены целиком до сопоставимого
эксперимента. Их 721 177 входных токенов сохранены отдельно как затраты подготовки,
не скрыты и не вычтены из результатов. Основное сравнение использовало небольшие
части. Это выявило практическую необходимость проверять полноту tool output,
а не полагаться только на размер сохранённого пакета.

Каталог и память в этом снимке генерировались кодом AISpa без отдельного модельного
вызова для их создания. Затраты на исходную документацию, разработку продукта и
стенд не входят в сравнительный эффект. Два повтора одного проекта не доказывают
кратную или универсальную экономию, а фиксированное число чтений не измеряет
возможную экономию на количестве обращений к модели.

## Ограничения и следующий шаг

Осталось одно неблокирующее улучшение примера: у сообщения о незакрытой CSV-кавычке
нет номера строки. Неверный файл отклоняется, но диагностика не объявляется улучшенной.

В этом нативном прогоне не потребовалось исправление после FAIL первого критика:
все критики дали PASS. Поэтому модельный цикл repair здесь не подтверждён;
автоматические проверки движка не подменяют такой пилот. Отдельно остаются
полные модельные прогоны Claude Code, Cursor и Windows-host, а также другие
размеры проектов и неизвестные вопросы при восстановлении памяти. Клон не является
песочницей ОС или сетевой изоляцией.

Для опубликованного примера добавлены автоматические проверки в матрицу Windows,
macOS и Linux с Python 3.11/3.13. Результат относится к конкретному commit в
[Actions](https://github.com/alexfisenkov/aispa/actions/workflows/checks.yml);
это проверка программы на ОС, не модельный прогон в приложении.

Следующее обоснованное улучшение AISpa — уменьшить каталог и не передавать весь
индекс там, где нужные пути уже известны. После этого повторить тот же замороженный
эксперимент и проверить более крупный проект. Заявлять экономию «в разы» сейчас
оснований нет; статус стабильного выпуска не меняется.
