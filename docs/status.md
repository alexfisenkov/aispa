# Текущий статус AISpa

Сверено 23.10.2026. Эта страница объединяет текущий выпуск, подтверждённые
результаты и оставшиеся ограничения. Датированные планы, решения и протоколы
сохраняют состояние своего этапа; их старые слова «кандидат» или «открыто»
сами по себе не обозначают новую незавершённую работу.

## Выпуск и доставка

Стабильная **[0.3.5](https://github.com/alexfisenkov/aispa/releases/tag/v0.3.5)**
опубликована. Source commit — `d1da9cd205b0df86f3d129a5d175340b21e0f1ac`.
PR №9 слит; финальная адресная CI прошла шесть jobs
macOS/Linux/Windows × Python 3.11/3.13. Ресурсы Release и все 89 файлов
пакета сверены с точной сборкой. Четыре локальные установки на Mac обновлены
штатным CLI и отвечают `current`; сохранены резервные копии 0.3.4.
[Состав](release-0.3.5.md), [проверки и квитанции](validation-0.3.5.md).

Это адресные инженерные проверки и проверка доставки. Полный модельный
проект в каждой из шести сред заново не запускался. Активные проекты и
их закреплённые runtime не мигрировали.

## Что ещё не подтверждено

| Проверка | Последнее свидетельство и граница |
|---|---|
| Обновление через модель Claude Code | Узкая попытка 0.3.3 → 0.3.4 остановилась до команд навыка на HTTP 429. Повтор не подтверждён. |
| Обновление через отдельный Codex CLI | Та же проверка остановилась до навыка на HTTP 400. PASS нативного субагента Codex не является PASS отдельного клиента. |
| Отказ от установки и графические кнопки выбора | В узком нативном испытании не проверялись; согласие было отдельным текстовым сообщением тестового собеседника. |
| Полные модельные проекты во всех средах и пользовательские Windows-конфигурации | Проверка файлов, CLI, нативного обнаружения и CI не заменяет такую приёмку. |
| Экономия полного процесса и преимущество продуктивности | Общего подтверждения нет. Последний одиночный повтор принят 47/47, но заметной экономии не показал. |

Источники: [нативное обновление](validation-0.3.4-native-update.md),
[границы 0.3.5](validation-0.3.5.md#границы-проверки),
[повтор и метрики](validation-lean-service-single-repeat.md),

Новые полные модельные прогоны не требуются для этой уборки и не запускаются
без отдельного разрешения владельца. Эти ограничения не превращаются в PASS
от смены номера версии или от завершения инженерной CI.

## Инженерный долг и намеренные ограничения

A10-D02 остаётся инженерным долгом: журнал хранит полные состояния, а
повторная проверка SHA требует чтения журнала. Для очень длинных прогонов
не реализован постоянный проверяемый индекс или delta history.
[Исходная запись](decisions.md) сохраняет это ограничение; новый замер
производительности при уборке не проводился.

- При отложенной **финальной** задаче сдача невозможна: сохраняется требование
  актуального общего ревью. Обычная отложенная задача может уйти в остатки,
  если финальная задача завершена и остальные условия сдачи выполнены.
  Это действующий guard, а не обещанное исправление;
  [контракт выпуска](release-0.2.0.md#режимы-проверки).
- Активный прогон продолжает работать на закреплённом runtime; автоматической
  миграции истории на новый движок нет.
- Смысловое качество результата и независимость участника не доказываются
  схемой или хешем. Остальные технические границы —
  [ограничения испытаний](testing.md#сохраняющиеся-ограничения).
