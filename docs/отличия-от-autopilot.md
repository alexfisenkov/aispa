# Чем AISpa 1.0 отличается от Autopilot 2.2.0

Основа — Autopilot 2.2.0 Ника Велса (коммит `25b5fba`, MIT). Всё, чего нет в
списке ниже, взято как есть: восемь этапов, список требований из дословных
цитат, четыре проверки (G1–G4), `ap.py` с вызовом на каждое событие, шаблон
панели. Правки сделаны по решениям владельца: AISpa должна быть больше про
бриф, то есть про то, что хочет человек, и ничего лишнего не добавлять.

Каждая строка: файл — что изменено — ради чего.

## Про бриф

- `phases/1-manifest.md` — способ, которым человек заказал результат (кнопки,
  экраны, роли), записывается отдельной строкой списка требований; личные
  данные третьих лиц в брифе заменяются видимой заглушкой, как секреты — чтобы
  способ нельзя было подменить молча, а публичную папку прогона можно было
  коммитить.
- `phases/2-briefing.md` — каждый ответ человека на вопрос попадает в бриф;
  до плана ничего не ставится и не запускается вне проекта — чтобы ответ не
  терялся, а работа не выходила за проект.
- `phases/3-spec.md` — подмена заказанного способа считается «покрыто
  наполовину» — чтобы проверка описания ловила её.
- `phases/4-plan.md` — критерий шага пишется словами брифа; список рисков, при
  которых шаг проверяется отдельно, расширен: к входу, паролям, ключам, деньгам
  и удалению данных добавлены собственный код выдачи и проверки доступа и код,
  который обрабатывает личные данные — чтобы проверять там, где ошибка дорога.
- `prompts/executor.md` — исполнитель, которому нужен другой способ, чем в
  брифе, останавливается и сообщает, а не меняет молча.
- `prompts/review.md` — проверяющий отмечает подмену способа как «частично»;
  тот же расширенный список рисков; находка по безопасности и потере данных в
  сценарии из брифа только чинится, в отчёт её не откладывают.
- `phases/rationalizations.md` — подмена способа добавлена в список красных
  флагов.
- `tools/ap.py` — `check-plan` не пропускает требование, снятое без слов
  человека: цитата в «Основании» ищется во всех файлах брифа, а цитата из
  самого требования его словами не считается.
- `phases/1-manifest.md`, `phases/8-final.md` — каждое отложенное требование
  попадает в первый раздел отчёта «Решения, принятые за тебя», рядом с
  допущениями, в любом режиме; «Что не вошло» — только снятые словами человека.
  Образец отчёта открывается этим разделом — чтобы отложенное не терялось.
- `phases/8-final.md`, `phases/9-memory.md` — слепая приёмка идёт тем способом,
  который назван в брифе; найденное расхождение чинится отдельным шагом, затем
  одна повторная слепая проверка только расходившихся пунктов (проверяющий
  получает свои прежние строки по ним, но не описание и не список требований);
  в отчёт попадает только остаток; порядок финала выровнен между файлами —
  чтобы отчёт говорил о том, что осталось после починки.

## Модели

- `SKILL.md`, `phases/4-plan.md`, `phases/5-subagents.md` — одна таблица ролей
  для Claude Code и Codex: проверяющие, сильный исполнитель (шаг с риском или
  `сильная`, ремонтные шаги, перезапуск после сбоя), обычный исполнитель и два
  вида механики; у каждой роли своя модель и усилие; ничего выше Opus · high и
  Sol · high, без Fable, Astra и наследования модели чата. Для главного чата
  дан совет по модели — чтобы цена была предсказуемой.
- `agents/claude-code/` (шесть файлов), `agents/openai.yaml` — готовые агенты,
  где модель и усилие заданы заранее; в Codex они передаются явно при запуске.
  Проверяющий агент код не правит; обычный исполнитель берёт и роли не-шага
  (разведка кода, память, решения) по промпту координатора.

## Непрерывность и Codex

- `SKILL.md` (описание) — запуск по `/aispa` в Claude Code и по `$aispa` в
  Codex; вызов без задачи в обеих средах продолжает прерванную сборку.
- `phases/0-preflight.md` — проект с прогоном прежней AISpa (папка `.aispa/`):
  его состояние читается один раз закреплённой копией прогона, незаконченный
  прогон продолжается ею; если субагенты выключены, сборка останавливается с
  понятным объяснением, а не идёт молча без них.
- `phases/5-subagents.md` — исполнителей волны ждут в том же ходе.
- `phases/0-instruments.md` — в Codex панель открывается во встроенном
  браузере; шаблон панели берётся из папки открытого `SKILL.md`, запасной поиск
  включает `~/.codex/skills` и смотрит только в папки `aispa`.

## Честное время

- `tools/ap.py`, `phases/dashboard-template.html`, `tools/eta-honesty.cjs` —
  история прогонов даёт диапазон по медианному значению и квартилям; без замеров
  панель пишет «пока не знаю» и не выдумывает числа; при затянувшейся работе
  говорит «идёт дольше обычного». `tools/eta-honesty.cjs` проверяет, что
  обещанный диапазон попадает в фактическое время.

## Имя, слова и поставка

- Везде — `skills/aispa/`, рабочая папка `.aispa-work/` (коммитится), метки
  памяти, переименованный код `ap.py` и тест на `.gitignore`.
- `SKILL.md`, `phases/`, `tools/ap.py`, панель — слова для человека по-русски
  и просто: этапы Подготовка · Требования · Вопросы · Описание · План ·
  Разработка · Проверка · Приёмка, единица работы — «шаг».
- `SKILL.md` (раздел «Outside a run») — «обнови AISpa» проверяет, готовит и
  ставит новую версию только после «да»; вопрос про саму AISpa — ответ из
  справочника пакета. `phases/0-instruments.md`, `phases/0-modes.md`,
  `tools/ap.py` — строка о новой версии сверяется с репозиторием AISpa и
  предлагает сказать «обнови AISpa».
- `tools/install.py`, `tools/package_update.py`, `skills/aispa/tools/aispa.py`,
  `skills/aispa/tools/aispa_core/` — установка и обновление из опубликованного
  выпуска без аккаунта и токена GitHub, резервная копия и откат.
- `skills/aispa/references/support-faq.json`, `tools/render_support_faq.py`,
  `docs/support-faq.md` — справочник ответов на частые вопросы учеников и
  генератор, который сверяет ответы с файлами пакета.
- `tools/measure.py`, `tools/measure_wrapper.py` — инструмент сравнения AISpa и
  Autopilot на одном небольшом брифе; подмена способа, вмешательство человека
  или несданный прогон AISpa хотя бы один раз — «хуже». `tools/measure-run.py`
  — замер автора, дополненный ролями агентов AISpa.
- `.github/workflows/checks.yml` — один полный набор проверок, запускается
  вручную, на трёх системах.
- `LICENSE`, `skills/aispa/LICENSE` — два уведомления: на изменения и
  оригинальное Ника Велса; шапка с указанием основы в `ap.py`, шаблоне панели
  и `tools/measure-run.py`, потому что эти файлы живут и без пакета.
  `docs/design-autopilot.md`, `docs/benchmark-autopilot.md` — доводы и замеры
  автора с пометкой авторства; `phases/6-review.md` ссылается на них.
- `tests/` — тесты основы сохранены, добавлены тесты на правки выше.
