# Чем AISpa 1.0 отличается от Autopilot 2.2.0

Основа — Autopilot 2.2.0 Ника Велса (коммит `25b5fba`, MIT). Всё, чего нет в
списке ниже, взято как есть: восемь этапов, список требований из дословных
цитат, четыре проверки (G1–G4), `ap.py` с вызовом на каждое событие, шаблон
панели. Правки сделаны по решениям владельца: AISpa должна быть больше про
бриф, то есть про то, что хочет человек, и ничего лишнего не добавлять.

Каждая строка: файл — что изменено — ради чего.

## Про бриф

- `phases/1-manifest.md` — способ, которым человек заказал результат (кнопки,
  экраны, роли), записывается отдельной строкой списка требований; личные
  данные третьих лиц в брифе заменяются видимой заглушкой, как секреты — чтобы
  способ нельзя было подменить молча, а публичную папку прогона можно было
  коммитить.
- `phases/2-briefing.md` — каждый ответ человека на вопрос попадает в бриф;
  до плана ничего не ставится и не запускается вне проекта — чтобы ответ не
  терялся, а работа не выходила за проект.
- `phases/3-spec.md` — подмена заказанного способа считается «покрыто
  наполовину» — чтобы проверка описания ловила её.
- `phases/4-plan.md` — критерий шага пишется словами брифа; список рисков для
  точечной проверки сужен до выдачи и проверки доступа и обработки личных
  данных — чтобы проверять там, где ошибка дорога.
- `prompts/executor.md`, `prompts/review.md` — исполнитель, которому нужен
  другой способ, останавливается и сообщает, а не меняет молча; проверяющий
  отмечает подмену способа и смотрит безопасность и потерю данных в сценарии
  из брифа.
- `phases/rationalizations.md` — подмена способа добавлена в список красных
  флагов.
- `phases/8-final.md`, `phases/9-memory.md` — слепая приёмка идёт тем способом,
  который назван в брифе; найденное расхождение чинится отдельным шагом и
  проверяется заново, в отчёт попадает только остаток; порядок финала выровнен
  между файлами — чтобы отчёт говорил о том, что осталось после починки.
- `tools/ap.py` — `check-plan` не пропускает требование, снятое без слов
  человека: цитата ищется во всех файлах брифа; отложенное попадает в первый
  раздел отчёта.

## Модели

- `SKILL.md`, `phases/4-plan.md`, `phases/5-subagents.md` — одна таблица ролей
  для Claude Code и Codex: четыре класса исполнителей, у каждого своя модель и
  усилие; ничего выше Opus · high и Sol · high, без Fable, Astra и наследования
  модели чата. Для главного чата дан совет по модели — чтобы цена была
  предсказуемой.
- `agents/claude-code/` (шесть файлов), `agents/openai.yaml` — готовые агенты,
  где модель и усилие заданы заранее; в Codex они передаются явно при запуске.

## Непрерывность и Codex

- `SKILL.md`, `phases/0-resume.md` — вызов без задачи продолжает прерванную
  сборку, в том числе в новом чате.
- `phases/5-subagents.md` — исполнителей волны ждут в том же ходе.
- `phases/0-instruments.md`, `phases/0-preflight.md` — в Codex панель
  открывается во встроенном браузере; если субагенты выключены, сборка
  останавливается с понятным объяснением, а не идёт молча без них.

## Честное время

- `tools/ap.py`, `phases/dashboard-template.html`, `tools/eta-honesty.cjs` —
  история прогонов даёт диапазон по медианному значению и квартилям; без замеров
  панель пишет «пока не знаю» и не выдумывает числа; при затянувшейся работе
  говорит «идёт дольше обычного». `tools/eta-honesty.cjs` проверяет, что
  обещанный диапазон попадает в фактическое время.

## Имя, слова и поставка

- Везде — `skills/aispa/`, рабочая папка `.aispa-work/` (коммитится), метки
  памяти, переименованный код `ap.py` и тест на `.gitignore`.
- `SKILL.md`, `phases/`, `tools/ap.py`, панель — слова для человека по-русски
  и просто: этапы Подготовка · Требования · Вопросы · Описание · План ·
  Разработка · Проверка · Приёмка, единица работы — «шаг».
- `tools/install.py`, `tools/package_update.py`, `skills/aispa/tools/aispa.py`,
  `skills/aispa/tools/aispa_core/` — установка и обновление из опубликованного
  выпуска без аккаунта и токена GitHub, резервная копия и откат; обновление
  включается фразой «обнови AISpa» и ставится только после «да».
- `skills/aispa/references/support-faq.json`, `tools/render_support_faq.py`,
  `docs/support-faq.md` — справочник ответов на частые вопросы учеников и
  генератор, который сверяет ответы с файлами пакета.
- `tools/measure.py`, `tools/measure_wrapper.py` — инструмент сравнения AISpa и
  Autopilot на одном небольшом брифе.
- `.github/workflows/checks.yml` — один полный набор проверок, запускается
  вручную, на трёх системах.
- `LICENSE`, `skills/aispa/LICENSE` — два уведомления: на изменения и
  оригинальное Ника Велса; шапка с указанием основы в `ap.py` и шаблоне панели,
  потому что эти файлы копируются в проект без пакета.
- `tests/` — тесты основы сохранены, добавлены тесты на правки выше.

его разбор аудитов — это его продукт; ссылки на них — в его репозитории.
