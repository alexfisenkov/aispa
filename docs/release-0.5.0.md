# AISpa 0.5.0

Быстрее, дешевле и строго по брифу. Всё новое поведение включается флагами
политики только при новом `init`; начатые прогоны идут своей закреплённой
копией навыка, их журнал старого формата читается без изменений. Факт
проверок, приёмки и выпуска — [протокол](validation-0.5.0.md).

## Состав

- **Проверки задачи.** Критик читает изменения своей попытки и файлы, на
  которые опираются её критерии; принятые предки перепроверяются, только если
  попытка задела их файлы. Блокирует короткий список: расхождение с брифом
  (в том числе кнопки, подменённые командами), сломанный сценарий,
  безопасность, потеря данных, падающие тесты. Остальные замечания копятся и
  чинятся одной задачей перед финалом.
- **Режимы — только число ревью.** Тяжесть задачи определяет движок.
  «Быстро» — критик у задач с деньгами, ключами, доступами, личными данными и
  обязательными сценариями, ветку смотрит один проверяющий; «Сбалансированно»
  (по умолчанию) — критик у всех тяжёлых задач, двое; «Максимум» — критик у
  каждой задачи, второй круг у тяжёлых, трое. Маленькому проекту советуется
  «Быстро», режим ставит выбор пользователя.
- **Бриф на входе и на выходе во всех режимах.** Два независимых читателя и
  сверка спецификации до `seal`; проверка ветки, финальный ремонт и слепая
  приёмка из чистого клона с ремонтом расхождений — в конце.
- **Модели по ролям.** Одна [таблица маршрутов](../skills/aispa/references/model-routing.md)
  «класс роли × среда» для Claude Code и Codex. Субагентам движок не даёт Fable,
  Astra, `inherit`, пустую модель и усилие выше high; недоступная модель —
  блокер с вариантами, без тихой замены. В Claude Code усилие задают файлы
  агентов `aispa-*`, которые ставят установщик и обновление; недостающие после
  обновления старой версией — `update-agents --confirm`. Главному чату модель
  только советуется.
- **Честное время.** Остаток — только по замерам этого прогона или прошлых
  прогонов на этом компьютере; без данных — «пока не знаю». Простой и
  ожидание владельца отдельно от работы. Инструменты `tools/measure.py` и
  `tools/eta_honesty.py` в репозитории (не в пакете).
- **Меньше ходов координатора.** `task-open` и `task-close` — по одному вызову
  движка; карточки ролей — при назначении; план и исследование не
  пересобираются без изменения входов; краткий ответ по умолчанию, полный —
  `--full`; SKILL.md держит постоянный маршрут, ветки — в справочниках.
- **Лёгкий журнал и спокойная панель.** Строки-дельты с опорными точками и
  проверенным кэшем; панель не пересчитывает неизменный журнал, молчит в
  скрытой вкладке, пишет «Снимок считается» и открывается один раз.
- **Вопросы учеников.** Решения по требованиям, точечный переплан после
  правки брифа, отчёт о продолжении с изменениями кода, ревизия формы
  проверки только добавлением ссылки на проверку до изменений, понятный
  блокер выключенных субагентов, понятное сообщение о лимите GitHub без
  аккаунта и токена. [Справочник](support-faq.md) переписан простыми словами:
  27 записей одного канона `skills/aispa/references/support-faq.json`.

Прежний рабочий кандидат масштаба и надёжности не продолжается и вытеснен этой
сборкой ([статус](status.md)).

## Порядок выпуска

Выпуск делает только оркестратор сборки, по одному оператору Git. До «да»
владельца ничего не сливается, не тегируется и не публикуется, установки не
меняются.

### 1. До вопроса владельцу

1. На финальном SHA ветки — один полный `python3 -B -m unittest discover -s tests -v`,
   один `node --test tests/dashboard.test.cjs` и один ручной `checks.yml` со
   `scope=full`. Если Actions недоступны — режим владельца для локального
   выпуска с прямой пометкой в протоколе.
2. Слепая приёмка сборки по брифу владельца из чистого клона итогового коммита:
   свежий судья, не больше двух циклов «расхождения → ремонт → перепроверка
   расходившихся пунктов».
3. Замер против автопилота: оси сравнения и каждая ось, где AISpa хуже, с
   цифрами обеих сторон.
4. Результаты вписаны в [протокол](validation-0.5.0.md).

### 2. Один вопрос владельцу одним сообщением

В сообщении:

- слияние PR #14 в `main`, тег и Release `v0.5.0`, обновление его установок
  `~/.claude/skills/aispa` и `~/.agents/skills/aispa` и агентов `aispa-*`;
- итог слепой приёмки сборки: «проверено / совпало / расхождения»;
- невыполненные оси сравнения с автопилотом, если они есть;
- **вопрос 1 — запуск по явному вызову.** В пакете
  `disable-model-invocation: true`, в карточке Codex
  `allow_implicit_invocation: false`, в `description` — «только по явному
  вызову». В локальной копии владельца флаг снят без коммита. Какое значение
  будет в 0.5.0? Без ответа обновление его установки вернёт `true`, заменив
  локальную правку;
- **вопрос 2 — исключение для агентов `aispa-*` в правиле владельца о моделях
  субагентов.** Правило допускает только opus и sonnet, а
  `aispa-mechanic-scripted` по таблице маршрутов — на Haiku. Добавить
  строку-исключение для `aispa-*` по таблице маршрутов скилла (Haiku — только у
  `aispa-mechanic-scripted`) или оставить правило как есть?

### 3. После «да»

1. Если по вопросу 1 выбрано другое значение — правка флага, карточки Codex и
   `description` отдельным коммитом в ветке; затем пересчёт SHA привязок FAQ,
   пересборка `docs/support-faq.md` генератором, проверка записи «Как запустить»
   и правка теста `test_invocation_flags_unchanged`; адресные тесты.
2. Слияние PR #14, тег `v0.5.0` на коммите слияния, опубликованный Release.
3. `release.yml` заливает три ресурса (`aispa.zip`, `aispa-update.json`,
   `install.py`); проверить чтением, что их ровно три и что они совпадают с
   локальной сборкой `tools/package_update.py` точного коммита.
4. Для `~/.claude/skills/aispa` и `~/.agents/skills/aispa`: `update-check` →
   `update-prepare` → проверка кандидата → `update-apply --candidate … --confirm`.
   Агенты `aispa-*` в `~/.claude/agents/` — штатным обновлением или
   `update-agents --confirm`; изменённые файлы не перезаписываются.
5. **Условная правка правила.** Только если владелец ответил «да» на вопрос 2:
   строка-исключение для `aispa-*` в его правиле о моделях субагентов, затем
   прогон его скрипта проверки моделей субагентов — код выхода 0. При «нет»
   или без ответа: агенты ставятся, правило не трогается, а в протоколе прямо
   сказано, что скрипт проверки владельца будет отмечать
   `aispa-mechanic-scripted`.
6. `update-check` в обеих установках отвечает `current` 0.5.0.
7. В README, `AGENTS.md`, [статусе](status.md) и протоколе записаны source
   commit, ссылка на Release и факт обновления установок. В первой строке
   README ссылка «AISpa 0.5.0» до публикации ведёт на этот документ; после
   публикации Release она заменяется на
   `https://github.com/alexfisenkov/aispa/releases/tag/v0.5.0`.

### Что не делается автоматически

Слияние, тег, Release, обновление установок и правка правил владельца не
выполняются на основании этого документа без его отдельного «да». Ученикам ни
в группе, ни в личных сообщениях ничего не отправляется. Активные прогоны и
их закреплённые копии не меняются.
