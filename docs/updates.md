# Обновление AISpa

Первую установку делает `install.py` — [установка](install.md). Здесь — как
обновить уже установленную AISpa и как вернуть прежнюю, если что-то не так.

## Как обновить: фраза «обнови AISpa»

Скажите агенту **«обнови AISpa»**. Дальше он идёт так:

1. **Проверка.** `python3 <папка-навыка>/tools/aispa.py update-check` — только
   чтение, ничего не меняет. Источник — опубликованные выпуски
   `alexfisenkov/aispa` на GitHub; ветки, черновики и голые теги Git не подходят.
2. **Кандидат.** Если вышла новая версия — `update-prepare`: скачивает выпуск,
   сверяет `aispa-update.json`, SHA-256 архива, состав, размеры, права и
   контрольные суммы файлов, связывает commit с тегом выпуска. Кандидат ждёт
   рядом с папкой навыка в `.aispa-update-<id>/`; установленная AISpa пока
   не меняется. Агент показывает обе версии и что изменится.
3. **«Да».** Только после вашего «да» —
   `update-apply --candidate <candidateId> --confirm`. Если без вашего ведома
   изменились файлы установленной AISpa, установка их не затирает и просит
   подготовить кандидата заново.
4. **Резервная копия.** Прежняя версия остаётся рядом в
   `.aispa-backup-<id>/package`, а `receipt.json` хранит путь, версии и хеши.
   Сохраните `backupId` из ответа: по нему делается откат.

После установки агент перечитывает `SKILL.md`. Если ошибка случилась на любом
шаге, работа идёт дальше с установленной версией.

Когда начинается сборка, AISpa сама проверяет выпуски. Если вышла новая
версия, в начале будет одна строка: «вышла AISpa X (у тебя Y) — скажи „обнови
AISpa“, поставлю после твоего „да“». Посреди сборки AISpa не обновляется.

| Ответ проверки (`status`) | Что делает агент |
|---|---|
| `available` | при `installAllowed` готовит кандидата |
| `current`, `no_release` | продолжает с установленной версией |
| `offline` | коротко говорит, что проверка недоступна, и продолжает |
| `invalid_release` | оставляет установленную версию и не обходит проверку |

Обновление не трогает папку, которая лежит под Git с файлами пакета, копию
внутри сборки (`.aispa/runs/…/runtime`) и папку, внутри которой есть `.aispa/`.
Причину называет поле `installReason`.

Если AISpa стоит в нескольких местах (в проекте и общая), каждую копию
обновляют отдельно.

## Агенты Claude Code

Шесть агентов `aispa-*.md` обновляются вместе с навыком и с той же резервной
копией. Проверка показывает недостающие и отличающиеся файлы. Недостающие
ставит `python3 <папка-навыка>/tools/aispa.py update-agents --confirm`; файл
с тем же именем, но другим содержимым, не перезаписывается.

## Откат

После вашего выбора:

```text
python3 <папка-навыка>/tools/aispa.py update-rollback --backup <backupId> --confirm
```

Откат разрешён, только если ни сохранённая, ни установленная версия не
менялись после установки. Новая версия при откате тоже сохраняется рядом.

**Если обновление оборвалось** (выключили питание, процесс убили), папки навыка
может не оказаться на месте, а `receipt.json` останется в состоянии
`installing`. Штатный откат такую установку не принимает. Восстановление
вручную:

1. Убедитесь, что процесс обновления остановлен.
2. Найдите рядом `.aispa-backup-<id>/receipt.json` с нужным путём; ничего не
   удаляйте.
3. Сверьте `package` из резервной копии с `backupDigest` из `receipt.json`
   (состав, размеры, права, SHA-256). Не сходится — остановитесь и сохраните
   все копии.
4. Если папки навыка нет, а копия сошлась, верните `package` на путь из
   `receipt.json`. Если папка есть, сначала выясните, закончилась ли установка.
5. Проверьте версию и состав. Только потом уберите соседний
   `.aispa-update-lock-<hash>`.

Соседние папки кандидатов и резервных копий сами не удаляются.

## Проекты, начатые в прежней версии AISpa

Незаконченная сборка в папке `.aispa/` продолжается своей копией внутри
сборки. Обновление установленной AISpa эту копию не меняет и в неё не ставит.
Новые сборки идут установленной версией и пишут в `.aispa-work/`.

## Сборка файлов выпуска

Из корня репозитория, по сохранённому commit:

```text
python3 tools/package_update.py --commit <точный-SHA> --output <свободная-папка>
```

Команда читает только объекты Git этого commit: `skills/aispa/` и корневой
`LICENSE`. Незакоммиченные правки не попадают. Получаются `aispa.zip`,
`aispa-update.json` и `install.py` одного commit; одинаковый commit даёт
одинаковый архив. Команда ничего не публикует.

Сборка отказывает и называет файл, если в commit нет хотя бы одного из
обязательных: `SKILL.md`, `LICENSE`, `tools/aispa.py`,
`tools/aispa_core/__init__.py`, `tools/ap.py`, `phases/dashboard-template.html`,
`prompts/executor.md`, `prompts/review.md`, шести `agents/claude-code/aispa-*.md`,
`agents/openai.yaml`. Отказывает она и тогда, когда `metadata.version` в
`SKILL.md` не равна `VERSION` в `tools/aispa_core/__init__.py`.

Файлы к опубликованному Release прикрепляет
[`.github/workflows/release.yml`](../.github/workflows/release.yml): он
запускается на публикацию Release, собирает пакет из commit тега, сверяет
версию с тегом (`1.0.0` или `v1.0.0`) и прикрепляет три файла. Сам Release он
не создаёт и уже прикреплённые файлы не перезаписывает. Пока файлы не
прикреплены, проверка обновления может ответить `invalid_release`; установленная
версия при этом работает.

## Формат файлов выпуска

Архив хранит файлы под `aispa/`. `aispa-update.json`, schema 1:

```json
{
  "schema": 1,
  "repository": "alexfisenkov/aispa",
  "version": "1.0.0",
  "commit": "<40 строчных hex-символов>",
  "archive": {"name": "aispa.zip", "sha256": "<64 строчных hex-символа>"},
  "files": [
    {"path": "SKILL.md", "sha256": "<SHA-256>", "size": 1234, "mode": 420}
  ]
}
```

`files` перечисляет весь пакет. `mode` — 420 (0644) или 493 (0755). Версия
кода, `aispa-update.json` и Release совпадают; commit совпадает с commit тега.

Пределы: 2048 файлов, 16 MiB на файл, 64 MiB распакованного пакета, 32 MiB
архива, 2 MiB метаданных. Ссылки, особые файлы, небезопасные пути, повторы и
лишние файлы отклоняются. HTTPS и хеши привязывают файлы к выпуску этого
репозитория; это не отдельная цифровая подпись.
