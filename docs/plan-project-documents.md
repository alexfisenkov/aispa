# Проектные документы и замысел между запусками · 0.3.0

Поручение владельца от 22.10.2026: подхватывать существующие документы,
сохранять замысел проекта между запусками, дать ученику понятную карту;
без дублей и лишних согласований. Разрешены GitHub, выпуск 0.3.0 и обновление
локальных агентов после инженерных проверок. Новые полные модельные прогоны
и повторные сравнения с референсом не проводятся.

## Контракт

- Роли документов: interview, intent, spec, plan, index. Точные английские и
  русские имена в корне/docs распознаются; один безопасный кандидат связывается
  автоматически. Имя не доказывает смысл/одобрение документа: агент читает его.
- Несколько кандидатов не ранжируются по дате или удобству. Агент выбирает
  источник по действующему канону и регистрирует путь, прочитанный SHA и причину.
  Для аналогов под другими именами действует та же адресная команда. Один README
  может выполнять несколько ролей. Новых вопросов владельцу ради этой механики нет.
- Оригинал остаётся единственным редактируемым источником. В журнале — указатели,
  история выбора и неизменные снимки для проверки происхождения. Отдельного
  изменяемого реестра на стороне нет; выбор наследуется из предыдущего журнала.
- Текущий бриф и долгосрочный замысел разделены. Новые briefs/requirements/spec/tasks
  создаются заново; старые SPEC/PLAN не импортируются как новый scope или PASS.
  Исчезнувший/изменённый выбранный источник не заменяется другим автоматически.
- До idea/seal/spec/plan выбранный intent должен быть свежим. Если реального
  замысла нет, агент создаёт один документ/раздел на основе проекта и исходных
  слов, затем связывает его. Движок не выводит назначение всего проекта из
  последней задачи и не создаёт дубли корневых документов.
- Привязка нового SHA intent меняет смысловой basis; внешнее изменение источника
  снимает свежесть. Замысел является общим входом задач даже под нестандартным
  именем; пересечение записи требует зависимости. Справочные SPEC/PLAN показывают
  состояние, но не блокируют каждую задачу при обновлении статуса плана.
- Существующий `.aispa/context/INDEX.md` показывает по-русски: роль, оригинальный
  путь, зачем нужен файл, когда читать, свежесть. Служебные представления текущего
  запуска выделены отдельно; они не второй редактируемый канон. Краткая память
  даёт ссылку на замысел, не копирует весь документ. Известные пути не требуют
  полного каталога в пакете каждой роли.
- Новый policy-флаг включается только новым init. Закреплённые прежние runtime
  и журналы не мигрируют. Неизвестные/небезопасные/игнорируемые источники не
  обходятся подменой путей; snapshots проверяются по SHA.

## Проверка и доставка

Адресные проверки: распознавание/привязка/неоднозначность, несколько запусков,
пустой новый scope, stale/missing, Unicode/Windows/ссылки, отсутствие перезаписи,
читаемые реальные ссылки карты, сохранение лимита памяти, точный пакет роли,
повторная сверка после смены замысла. Затем независимые техника/риски/доказательства,
одна финальная CI на трёх ОС, публикация ресурсов точного commit и штатное
обновление пользовательских пакетов с резервными копиями.

Дополнительно исправляется воспроизведённая ошибка HTTPS updater на macOS:
Python без собственного CA bundle получает существующий системный CA;
проверка TLS не отключается, явные настройки и Windows trust сохраняются.

Результаты — [validation-0.3.0.md](validation-0.3.0.md).
