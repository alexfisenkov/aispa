# Изменения и проверки

## 19.10.2026 — начало разработки

Создан публичный репозиторий и собственная реализация AISpa. Первый коммит
содержал хранилище и 12 его проверок. После трёх раундов интервью реализованы
контракт требований, обязательное ядро, зависимые задачи, волны, проверка
текущего кода и итоговая приёмка с возможными второстепенными остатками.

Добавлены неизменные снимки брифов, точные цитаты, журнал с контрольной
цепочкой, запрет повторного ID требования, отказы на неполных доказательствах,
устаревание проверок и закреплённая копия движка для продолжения прогона.
Сброс задачи сбрасывает её зависимые задачи; новая редакция задачи не
сохраняет прежнюю отметку завершения.

Собственные инструкции и форматы описаны для трёх сред. Создан временный
HTML-экран без финального оформления; пользовательский текст вставляется
через textContent. Сервер пересчитывает свежесть при запросе состояния,
а при ошибке не возвращает старую положительную приёмку. Визуальную часть
дальше меняет владелец.

Проверки в `tests/` охватывают хранение, отрицательные переходы, полный
синтетический проход CLI отдельными процессами и локальный HTTP-сервер.
GitHub Actions запускается вручную; актуальный результат — в Actions
репозитория для соответствующего commit SHA.

Локальный итог этой итерации: 48 тестов прошли на macOS, полный сценарий CLI
выполнен, JavaScript временного экрана прошёл синтаксическую проверку Node.
Дополнительно проверены 15 локальных Markdown-ссылок и состав 27 публичных
файлов; исследовательские архивы и локальные пути в поставку не входят.

Модельные прогоны и пользовательская приёмка ещё не выполнены. Открытое и
план испытаний — [testing.md](testing.md). Релиз 1.0 не объявлен.


## 19.10.2026 — alpha.2: дизайн владельца, текущая работа и время

Внедрён предоставленный HTML-дизайн. Этапы и остатки сопоставлены с реальной
схемой движка. Добавлены текущие задачи, выполняющаяся проверка кода, часы
задач и прогона, остановка на паузе, диапазон ориентировочного ETA по измеренным
задачам. Чтение сервера остаётся доступным во время verify.

Исправлены два риска отображения: параметр предпросмотра не переопределяет
живую готовность, а ошибка связи снимает прежние положительные отметки.
В процессе работы пустой список итогов не подписывается «Остатков нет».

Добавлены проверки времени, оценок, чтения при занятом writer и поведения
доставляемого JS. Старые прогоны и установленный на машине набор skills не
переписывались. Визуальная проверка описана в [протоколе alpha.2](validation-alpha.2.md),
результат CI привязан к SHA в Actions; стабильный выпуск не создаётся.


## 19.10.2026 — alpha.3: роли задач, проектный контекст и обновления

Добавлены карточки worker/critic1/critic2/acceptor по проекту и задаче,
запись нативных назначений, отдельные адресные проверки, сдача исполнителя,
два раунда критики, связь исправлений с findings и отдельная приёмка задачи.
История попыток и цепочки доказательств сохраняются. Сброс или изменение
плана не дают новый бюджет критики; другая попытка требует нового брифа владельца.

Контракт зависимостей учитывает readZones, общие файлы и транзитивные входы.
Пересечение записи/чтения требует явной связи. Принятый потомок перепроверяет
предков и сохраняет inheritedProofs. Перед входом в следующую волну требуется
актуальная общая сверка полного брифа.

Init принимает фактический runtime. Добавлены инвентаризация без чтения
секретов, стабильные ссылки в правилах Codex/Claude Code/Cursor, резервные
копии и производные документы `.aispa/context/`. Обычное обновление контекста
не меняет корневые правила. Команды возвращают компактные квитанции;
context --write сохраняет отдельный пакет для роли.

Добавлен release-only updater: проверка, подготовка кандидата, подтверждённая
установка и откат с проверкой неизменности пакета. Git checkout и активные
runtime защищены. Инструмент package_update.py готовит архив и manifest из
точного commit без публикации. Аварийное восстановление между переименованиями
описано отдельно; независимой подписи издателя механизм не предоставляет.

Обновлены README, правила проекта, основной skill, процессы, контракты,
инструкции ролям и план испытаний. Подробности — [orchestration.md](orchestration.md)
и [updates.md](updates.md). Результаты итогового набора проверок привязываются
к проверенному commit отдельно; текущая запись не утверждает число PASS.
Нативные модельные прогоны не приписываются синтетическим тестам.
Release и стабильная версия этой итерацией не публикуются; пользовательские
установки и существующие прогоны автоматически не меняются.

Итог локальной проверки: 133 Python и 17 JavaScript тестов PASS. Настоящий
мини-пилот Codex подтвердил отказ приёмщика из-за потерянной трассировки
требования после двух PASS критиков. Детали и границы —
[протокол alpha.3](validation-alpha.3.md). Добавлен будущий workflow упаковки
ресурсов по событию Release published; сейчас он не запускался.


## 19.10.2026 — alpha.4: исследование, память и чистая проверка

Добавлен сбор содержимого существующего проекта с проверяемыми источниками и отдельный
отчёт агента по семи областям. Источники имеют точные пути и SHA-256; команды
подтверждаются буквальными строками. Секретные, игнорируемые, архивные и другие
неподходящие пути исключаются. Лимиты, неполные выдержки и пропуски явные.
Для нестандартных бизнес-модулей и тестов есть безопасные явные include.
Снимок переиспользуется ролями и обновляется перед новым планированием при
изменении источников.

Новый init сохраняет проверяемую историю прежних прогонов и их остатки.
Текущий объём и PASS не наследуются. Сопоставление обязательства требует
новых слов владельца и сохранения исходных критериев; закрытие — свежей
приёмки текущих задач. В контексте добавлены project-study.md и carryover.md.

Адресные пакеты имеют основной файл до 16 000 байт, с полными разделами по
ссылкам. Маршрутизация standard рекомендована только обоснованному low-risk
worker; оба критика и отдельный приёмщик остаются strong. Метрики usage
принимаются только как реальные данные среды, без оценки по длине текста.

Новые прогоны требуют перед итоговой приёмкой проверки точного commit в
чистом клоне. Предусмотрен отдельный пакет первоначальной проверки по брифу,
после которого проверяющий получает реестр для сверки. Клон не является
изоляцией ОС или сети, а независимость контекста обеспечивает координатор.

Обновлены README, карта модулей, контракты оркестрации и план испытаний;
добавлен [контур проектной памяти](project-memory.md). Итоговые проверки,
нативные прогоны, CI и ресурсы выпуска подтверждаются отдельно по фактическим
свидетельствам. Эта запись не утверждает их завершение или количество PASS.

Владелец разрешил prerelease 0.1.0-alpha.4. Это новое решение заменяет запрет
публикации для прежней итерации alpha.3; стабильный выпуск и автоматическая
установка в пользовательские каталоги по-прежнему не заявляются.

Финальная локальная проверка alpha.4: 238 Python и 18 JS тестов PASS,
actionlint PASS. Реальный переход файлов/CLI alpha.3 → alpha.4 проверен на
изолированном синтетическом проекте; глобальные установки не менялись.
Подробности и границы — [протокол alpha.4](validation-alpha.4.md).

## 19.10.2026 — alpha.5: нативная Windows

Добавлен общий ограниченный runner для verify/clean-verify: POSIX process group
и Windows Job Object с запуском команды только после назначения job. Вывод
ограничен, секреты проверяются и после лимита, дочерние процессы завершаются
при timeout и выходе родителя.

Чистый клон учитывает LF/CRLF как точное текстовое преобразование к Git blob;
реальное изменение, binary/-text, staged и untracked файлы не скрываются.
NTFS execute-бит учитывается через Git/manifest; junctions, ADS, device-имена
и drive-relative пути проверяются отдельно. Добавлены UTF-8 журнал/CLI, внешние
UTF-8 BOM inputs, Windows env, относительный Scripts/python.exe, безопасное
сравнение пакетов updater и инструкция PowerShell.

Локальный macOS-набор: 292 теста, 275 исполненных PASS, 17 Windows-only SKIP;
18 JS тестов PASS, actionlint и diff-check PASS. Полная финальная матрица
GitHub проверяет macOS, Windows и Linux на Python 3.11/3.13. Её фактический
результат привязывается к commit в Actions/Release; локальный результат не
заменяет нативную Windows-проверку. Два круга критики задач сохранены.

Ограничения: клон не sandbox; полная изоляция системных пакетов, native-host
прогоны Codex/Claude Code/Cursor на ученических машинах, сетевые/нестандартные
файловые системы остаются отдельными испытаниями. Tracked symlinks, submodules,
внешние Git-фильтры/encoding/ident и SHA-256 Git repositories отклоняются явно.
