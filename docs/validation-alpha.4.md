# Проверка alpha.4 · 19.10.2026

## Подтверждено локально

- Python 3.14/macOS: `python3 -B -m unittest discover -s tests -q` —
  238 тестов PASS, 89.622 с на финальном наборе исходников.
- `node --test tests/dashboard.test.cjs` — 18 тестов PASS.
- `actionlint` и `git diff --check` — PASS.
- Публичные исходники проверены на секреты, личные home-пути и посторонний
  брендинг; синтетические чувствительные значения в тестах собираются во
  временных фикстурах. Markdown-ссылки проверены на существование.
- Реальный пакет alpha.3 из commit 512dc5b использован для создания закрытого
  синтетического прогона. Затем текущая alpha.4 создала следующий прогон,
  перенесла исходник и остаток, записала carry map. Закреплённый runtime
  прежнего прогона не изменился. Это проверка совместимости файлов/CLI,
  не новый нативный модельный прогон.

## Покрытие новых сценариев

- Три поколения прогонов: остатки, решения, первоначальные цитаты, попытки,
  причины отказов и ссылки на отчёты; отсутствие дубликатов и потери lineage.
- Новое разрешение на унаследованную работу, неослабленные критерии, свежие
  участники и две критики перед resolve. Исторические PASS не становятся текущими.
- Изменение кода или отмена после resolve возвращает обязательство в остатки,
  сохраняя неизменную квитанцию прежнего решения.
- Чистый Git-клон: отдельные файлы/objects, точный HEAD, отсутствие игнорируемых
  локальных зависимостей и секретного окружения. Проверены реальная offline
  установка wheel по hash-lock в clone-local venv, timeout с дочерним процессом,
  изменения source/clone и устаревание commit.
- Отклоняются обнаруживаемые ссылки команды на исходную .venv/файлы, включая
  symlink, relative paths и строковые литералы. Полная изоляция системных пакетов
  не заявляется: зависимости проекта устанавливаются внутри клона.
- Первичные blind-наблюдения сохраняются до выдачи reconciliation-пакета.
  Повтор prepare/verify того же кандидата не разрешает заменить их. Новый
  кандидат требует нового приёмщика и сохраняет цепочку предыдущих наблюдений.
- Покрываются исходные цитаты, исторические applicableQuotes и явные решения
  владельца drop/defer/restore; неуспешное действующее требование не скрывается
  через сопоставление с дополнительной функцией или исключением.
- Исследование проекта: источники и SHA, семь областей, реальные команды,
  явное неизвестное, безопасные include, новые/изменённые исходники,
  исключение секретов, пропуски и ограничение размера.
- Большие пакеты разделяются без потери данных: конверт до 16 000 байт,
  полные обязательные sections. Малые пакеты не требуют лишних чтений.
  Проверены рекомендации моделей, включая повторные попытки между прогонами,
  и защита от двойного учёта реальных usage-метрик.
- CLI проверяет фактическое выполнение carry, обязательность discovery,
  clean-run и blind, полный синтетический путь через две критики до finish.

## Независимый обзор

В двух раундах устранены: коллизия argparse action, отказ переноса из прошлой
версии, обход первичных наблюдений повтором clean-verify, использование исходной
venv, потеря причин отказов, устаревшее resolved и неполные исторические источники.
Повторные кодовый и итоговый обзоры — PASS. Это отдельно от результатов тестов
и не заменяет GitHub CI/публикацию.

## Выпуск и границы

Владелец разрешил предварительный Release alpha.4 после проверок. Финальный
CI привязывается к точному commit в GitHub; workflow Release прикрепляет
воспроизводимые aispa.zip и aispa-update.json. Результат публикации и контрольные
суммы берутся из фактического Release, а не из этой предварительной записи.

Полные нативные прогоны alpha.4 в Codex, Claude Code и Cursor, сравнительные
измерения токенов/стоимости и стабильный выпуск остаются открытыми испытаниями.
Предыдущий нативный мини-пилот относится к alpha.3. Записанный native ID не
аутентифицирует модель; цитата не удостоверяет авторство реплики, а SHA не
доказывает смысловую правильность наблюдения. Clean-clone — не песочница;
Windows и автоматическая миграция активного старого runtime не поддерживаются.
Пользовательские глобальные установки в этой итерации не изменяются.
