# Проверка продукта

Документ нужен исполнителям и приёмщику для выбора проверок. Команда полного набора: python3 -m unittest discover -s tests -v. Требуются положительные сценарии и отказы, а не проверка только наличия функций.

Для домена проверить сортировку по убыванию priority, сохранение исходного порядка при равенстве, пропуск слишком длинной задачи с продолжением, нулевой бюджет, пустой CSV и повторяемость. Проверить границы minutes 1 и 480, бюджета 0 и 1440, неверные целые, лишние и недостающие столбцы и UTF-8 BOM.

Для CLI проверить JSON в stdout и --output, ненулевой код при неверном входе, stderr, отсутствие нового файла при ошибке и сохранение прежнего файла. Обязательно сравнить байты исходного CSV до и после успешного и неуспешного запуска. Smoke-сценарий должен реально запустить модуль с examples/tasks.csv.

Чистая приёмка использует Git-клон точного коммита; локальные .venv и .env туда не переносятся. В этом проекте нет внешних зависимостей, поэтому установка пакетов не требуется. Доказательство содержит команду и реальный вывод. Модельная оценка и успешный unittest — разные виды свидетельств.
