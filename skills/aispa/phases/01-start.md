# Старт, среда и контекст

Читай после [основного маршрута](../SKILL.md) при новом прогоне или
возобновлении. Установи физический корень проекта и действующие правила.
`--runtime codex|claude-code|cursor` бери из фактической среды, не из имени
каталога и не из догадки по переменным. Когда среда известна, не спрашивай
её у владельца. PowerShell и нативная Windows: [runtimes](../references/runtimes.md).
`init` принимает также `--depth strict|balanced|deep` (по умолчанию balanced):
это глубина сценариев, а не право сократить исходный заказ или проверки.

`init` инвентаризирует живую структуру, связывает правила среды и создаёт
`.aispa/context/` с INDEX, брифом, спецификацией, планом, решениями,
прогрессом, краткой памятью, требованиями и картой источников. Не навязывай
`src`, `backend` или новый каркас. Существующие правила сохраняются;
изменяемые правила получают резервную копию. При конфликте управляемого блока
сохрани пользовательский текст и назови конфликт. Не удаляй чужой Cursor rule.

Перед новым заказом прочитай `memory` и `.aispa/context/carryover.md` вместе с
исходными словами прежних незавершённых пунктов. Старые остатки сохраняются,
но не становятся автоматически новым заказом. Если владелец поручил их снова,
сохрани новый `brief`, создай неослабленное требование и до плана сделай
`carry <id> --action map --requirement R01 --brief B001 --quote …`.
`carry … --action resolve` возможен только после новой приёмки задачи.
Невзятые остатки остаются видимыми. Полное происхождение:
[continuity](../references/continuity.md).

Канон — Journal и неизменные источники `.aispa/runs/`; context — производное
представление. При сбое возобновляй сохранённый прогон, не редактируй JSON,
SHA и журнал вручную. Оборванный конец требует отдельного маршрута
[восстановления](06-continuity.md), а не нового `init`. Active runtime закреплён за прогоном. До первой
спецификации начни [исследование и план](03-plan.md).

Назначь координатора через `participant --role coordinator --runtime …
--native-id … --session …`, используя только ID из ответа нативной среды.
`participants` показывает записанных участников; запись ID означает
происхождение, а не криптографическую проверку модели. Сохраняй фактический
usage всех ролей адресно; неполный учёт не выдавай за полную стоимость.

Для текущего локального экрана используй `dashboard start` и сохрани точный
адрес из ответа. Повторный start должен переиспользовать действующий сервер;
`dashboard status` показывает его состояние, `dashboard stop` останавливает.
`dashboard archive` создаёт отдельный исторический снимок без живого опроса.
Русский/английский язык и системная/светлая/тёмная темы меняют только вид.
Ожидание ответа владельца видно отдельно и не запускает скрытый таймер.

## Документы и адресное чтение

Если нужные файлы уже известны, читай их напрямую. При точных существующих
zones/readZones пакет `context` может обойтись без каталога. При широких зонах
передай выбранные файлы повторяемым `context … --source <путь>`: это навигация,
не сужение требований либо входов проверки.

Когда пути надо найти, запроси `documents` — компактный каталог путей,
актуальности и описаний до 160 символов. `--detailed` используй для адресной
диагностики хешей и заголовков; не загружай весь каталог по привычке.
`discover` регистрирует безопасные собранные источники автоматически.
Дополнительно прочитанный файл регистрируй через
`document --path <путь> --sha256 <хеш прочитанных байтов> --summary <зачем файл>`.

Созданные движком Markdown-представления получают YAML-заголовок. Для Markdown,
который ты создаёшь или содержательно меняешь, используй `--write-header` до
проверки кода. Чужой frontmatter, исходные брифы, неизменные доказательства и
файлы только для чтения описывай в каталоге, не переписывая байты. YAML не
добавляют в код, JSON и специальные правила среды. Заголовок пишет один
согласованный исполнитель. При совместном редактировании используй каталог:
SHA-проверка сама по себе не является атомарным CAS.

После изменения документов, при возобновлении и перед каждой волной выполняй
`documents --refresh`. Изменённый SHA снимает актуальность старого описания;
автоматический refresh даёт только извлечённые ориентиры. После чтения
зарегистрируй новое содержательное описание с текущим SHA. Перед задачей и
после неё проверяй нужные пути. Если каталог чего-то не показал, запроси путь
адресно и проверь `documentWarnings`: они охватывают выбранные пути сверх
лимита выдачи. Заголовки помогают выбрать источник, но не заменяют полный
бриф, ограничения, expectedChecks или доказательство приёмки. Blind-приёмщику
каталог не передавай. Контракт: [documents](../references/documents.md).
