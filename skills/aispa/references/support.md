# Справочник поведения и безопасный аудит

Открывай, когда человек задаёт вопрос о самом AISpa или просит только осмотр
проекта. Обе ветки идут без прогона и без панели.

## Справочный ответ

Единственный канон Q/A — соседний `support-faq.json`, поставляемый вместе с
навыком. Открой его через read-only
`faq --version <обнаруженная версия> [--id <ID>]`: версия берётся у конкретного
установленного пакета или pinned runtime через его `--version`. Поля
`packageVersion`, schema и source files/SHA связывают канон с конкретными
байтами пакета; команда проверяет их и возвращает выбранные stable IDs с
canonicalSha256/sourceSha256. Несовпадение, неизвестный ID, изменённый источник
или отсутствие команды в старом runtime — явное ограничение, без подстановки
свежих правил: назови его. Не применяй новый FAQ к старому активному прогону.
Ссылки на repo docs не заменяют чтение пакетного JSON. Канон не содержит
собственного SHA внутри себя.

Отвечай словами записи, коротко и без внутренних терминов. Публичный
справочник содержит только общие оригинальные ответы. Источники учеников,
личные сообщения и технические receipts живых клиентских интеграций в него не
импортируются.

В корне Git-проекта есть authoring tool `tools/render_support_faq.py`; в
установленный пакет он не входит. Он использует тот же selector/renderer и
создаёт человеческий текст плюс отдельную generation receipt с точными IDs,
версией, canonical input SHA, source SHA и output SHA. Это локальное
происхождение текста, а не доказательство опубликованного Release, урока или
использования помощником. Видимые Q/A не содержат номера версии AISpa.

Режим вопросов (`auto/important/interview`), режим проверок
(`fast/balanced/max`) и охват/длительность интервью — разные настройки.
Обычные этапы после фиксации брифа идут самостоятельно; конкретные внешние
полномочия от этого не появляются. Временная пауза не обновляет прежний PASS:
возобновление проверяет изменения проекта, текущий run/pin и реальные доступы.

## Осмотр без разработки (audit-only)

Явный запрос «найди ошибки», «изучи работающий проект без изменений» выбирает
audit-only до обычного старта: `python3 "<skillDir>/tools/aispa.py" --root
"<projectRoot>" assess`. Сначала прочитай доступные правила проекта. Он не
вызывает update-check, init, Journal, команды проекта, браузер или дашборд и не
сохраняет compact-артефакт. Не расширяй его до полноценного запуска. Пропуски и
скрытые подозрительные значения явно названы; статический отчёт не
подтверждает runtime, тесты или безопасность всего проекта. Для ремонта нужно
исходное поручение владельца на изменение; уже данное поручение не спрашивай
повторно. Бюджеты — `assess --help`; полные границы —
[старт](../phases/01-start.md).
