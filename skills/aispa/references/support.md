# Справочник поведения и безопасный аудит

Единственный канон Q/A — соседний `support-faq.json`, поставляемый вместе с
навыком. Поля `packageVersion`, schema и source files/SHA связывают его с
конкретными байтами пакета. `faq --version <обнаруженная версия> [--id <ID>]`
проверяет их и возвращает выбранные stable IDs с canonicalSha256/sourceSha256.
Версию обнаруживай через `--version` именно того CLI, о котором задан вопрос:
установленного навыка либо pinned runtime проекта. Несовпадение, неизвестный ID,
изменённый источник или отсутствующий старый FAQ — явное ограничение, без
подстановки свежих правил. Канон не содержит собственного SHA внутри себя.

В корне Git-проекта есть authoring tool `tools/render_support_faq.py`; в
установленный пакет он не входит. Он использует тот же selector/renderer и
создаёт человеческий текст плюс отдельную generation receipt. В receipt есть
точные IDs, версия, canonical input SHA, source SHA и output SHA. Это локальное
происхождение текста, а не доказательство опубликованного Release, урока или
использования помощником. Видимые Q/A не содержат номера версии AISpa.

Режим вопросов (`auto/important/interview`), режим проверок
(`fast/balanced/max`) и охват/длительность интервью — разные настройки.
Обычные этапы после фиксации брифа идут самостоятельно; конкретные внешние
полномочия от этого не появляются. Временная пауза не обновляет прежний PASS:
возобновление проверяет изменения проекта, текущий run/pin и реальные доступы.

`assess` — короткий audit-only путь до init: [границы](../phases/01-start.md).
Он не выполняет найденные команды и не даёт разрешения чинить проект.
Факты и SHA не заменяют runtime-проверку; исключённые данные, лимиты и
неизвестное показываются явно. Публичный справочник содержит только общие
оригинальные ответы. Источники учеников, личные сообщения и технические receipts
живых клиентских интеграций в него не импортируются.
