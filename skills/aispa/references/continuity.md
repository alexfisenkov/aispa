# Исследование, память и экономия · alpha.4

## Сначала изучение

`discover [--include относительный/файл.py …]` собирает ограниченный набор
свидетельств и возвращает путь к JSON. Он читает реальные документы, манифесты
и характерные точки входа. Нет автоматического вывода «архитектура изучена» по
именам каталогов. Для предметных модулей и тестов исследователь добавляет include.
Повтор без include сохраняет прежнюю выборку; новый список её заменяет.

Коллекция содержит basis, пути и SHA-256 источников, фрагменты, дословно найденные
команды и явные пропуски. Секреты, личные данные, архивы, vendor, игнорируемые
файлы и symlinks не читаются как источники. Лимиты сборщика: до 48 источников,
до 6000 символов фрагмента, до 96 000 символов всего; файлы свыше 256 KiB
отмечаются пропущенными. Непрочитанное не считается изученным. При недостатке
свидетельств исследователь адресно читает безопасный исходник и сохраняет
ограничения, а не делает вывод по обрезанному фрагменту.

Отчёт `discover --file …`:

```json
{
  "basis": "<из коллекции>",
  "summary": "Что удалось установить о проекте",
  "observations": [
    {
      "area": "architecture",
      "text": "Конкретный вывод по изученному источнику",
      "sources": [{"path": "README.md", "sha256": "<из коллекции>"}]
    }
  ],
  "uncertainties": [
    {"area": "data", "text": "Схема данных пока не установлена"}
  ]
}
```

Пример неполный: все семь областей architecture, data, entrypoints, dependencies,
commands, conventions, risks должны иметь наблюдение или явную неопределённость.
Каждое наблюдение ссылается на собранный источник. Для команд добавляется поле
command с точным значением из коллекции. Происхождение проверяется кодом;
смысловая достоверность вывода остаётся работой исследователя и критиков.

`discovery` показывает свежесть. Изменение выбранного источника или появление
нового характерного источника требует повторной сверки перед следующим планом.
Во время исполнения старый снимок остаётся историческим контекстом; исходники
задачи защищаются её readZones и проверками текущего кода.

## Между прогонами

Init поддерживает read-only перенос истории schema 1 из alpha.1–alpha.3 и
текущей версии. Активный старый прогон продолжает свой закреплённый runtime;
это не миграция его движка. Неизвестная версия отклоняется.

Init сохраняет неизменный handoff предыдущего завершённого либо отменённого
прогона до переключения active pointer. При ошибке переноса прежний указатель
остаётся. Лимиты: до 1 MiB на исходный текст и до 16 MiB на handoff; при превышении
перенос останавливается без усечения и смены активного прогона.
Сохраняются исходные тексты и их происхождение, решения, исторические
приёмки, накопленные остатки и сведения об использованных попытках.

Новый прогон не получает старые PASS как доказательство. История принятых
результатов и текущие обязательства различаются. `.aispa/context/carryover.md`
показывает полную переданную историю; короткая memory.md содержит указатель
и число открытых пунктов. `memory` возвращает проверенный ledger.

Остатки не исчезают и не входят в новый объём автоматически. Прочитай их до
интервью и сопоставь с текущим поручением. В auto техническое решение принять
можно самостоятельно, но повторная попытка ранее порученной работы требует
реальных новых слов владельца, а не выдуманной цитаты.

```text
carry C-<id> --action keep
carry C-<id> --action map --requirement R01 --brief B001 --quote "Продолжи оставшийся экспорт"
carry C-<id> --action resolve
carry C-<id> --action defer --brief B002 --quote "Экспорт пока отложить"
```

Map выполняется после requirements, до plan. Новое требование сохраняет исходные
текст, вид, ядро и критерии; новые критерии можно добавлять. Map хранит старую
цитату вместе с новым разрешением. Resolve требует новых ролей и актуальной
приёмки всех задач. Изменившийся после resolve код возвращает пункт в открытые;
старое свидетельство разрешения остаётся историей. Отмена прогона также не
перевозит его текущую приёмку как действующую.

Drop/defer требуют нового источника владельца; defer остаётся видимым остатком.
Переименование семантически той же работы не даёт права обойти происхождение:
движок распознаёт точное совпадение текста, за смысловую связь отвечает координатор.
Старые источники сопоставленной работы входят в blind-пакет отдельно, без статусов
и чужих оценок; applicableQuotes определяет относящиеся к новому поручению цитаты.

## Контекст и модели

Контекст задачи содержит только её определения, нужные требования, зависимости,
ссылки на доказательства и карточку выбранной роли. История всей команды в него
не копируется. Большие поля выносятся в неизменные sections; конверт ограничен
16 000 байтами. Все необходимые sections обязательны к чтению. Исходные слова,
ограничения и критерии не обрезаются ради размера конверта.

Предпочитай задачи с законченным проверяемым результатом. Не дели один небольшой
результат на множество задач, каждая из которых потребует четырёх участников.
Разделяй при разных зависимостях/зонах, самостоятельном риске или чрезмерном
контексте исполнителя. Не сливай задачи через конфликт записи/чтения ради экономии.

План может добавить risk: low|normal|high и riskReason. Low допустим для
малорисковой изолированной реализации; объяснение обязательно. Для неё карточка
рекомендует standard. Фундамент, повторные попытки, normal/high, два критика
и приёмщик получают strong. Это уровни, не названия провайдеров. Реальную модель
выбирает host с учётом правил проекта. Недоступность выбора не обходят выдуманным
параметром; сохраняют текущую модель. Assign --model записывает фактический ID.

`usage --file …` принимает только реальные метрики native-вызова:

```json
{
  "actor": "<receipt.actor>",
  "callId": "<уникальный ID вызова>",
  "source": "<источник измерения среды>",
  "inputTokens": 1000,
  "outputTokens": 200,
  "cachedInputTokens": 700
}
```

Cached input входит в input, повторная запись того же вызова запрещена.
Без метрик возвращается unknown/null; байты не пересчитываются в придуманные
токены. Даже записанные метрики могут покрывать лишь часть прогона. Заявлять
экономию времени или денег можно только после сопоставимого измерения.
