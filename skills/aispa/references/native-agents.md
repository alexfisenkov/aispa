# Нативные среды AISpa: пути, участники и доказательства

Контракт кандидата **0.3.0**, проверка источников — **22.10.2026**.
Опубликованный выпуск 0.2.0 поддерживает три прежние среды. Наличие новых
адаптеров в исходниках не означает, что новый выпуск опубликован или прошёл
полный модельный сценарий в каждом приложении.

AISpa запускается только по явному поручению пользователя. Поддержка
frontmatter и список навыков у разных приложений различаются: обнаружение
`SKILL.md` само по себе не подтверждает автоматическое выполнение его правил.
Первое действие при явном запуске — `update-check` установленного пакета.

## Пути и правила проекта

В таблице приведены каталоги **навыка AISpa**, а не произвольного проекта.
`~` означает домашний каталог пользователя соответствующего приложения.

| `--runtime` | Проектная установка | Личная установка | Правила проекта |
|---|---|---|---|
| `codex` | `.agents/skills/aispa` | `~/.codex/skills/aispa`; современный общий каталог `~/.agents/skills/aispa` — через `--destination` | `AGENTS.md`; учитывать существующий `AGENTS.override.md` |
| `claude-code` | `.claude/skills/aispa` | `~/.claude/skills/aispa` | `CLAUDE.md` и общая карта `AGENTS.md` |
| `cursor` | `.cursor/skills/aispa` | `~/.cursor/skills/aispa` | `.cursor/rules/aispa.mdc`, `alwaysApply: true`; общая карта `AGENTS.md` |
| `openclaw` | `.agents/skills/aispa` | `~/.openclaw/skills/aispa` | `AGENTS.md` физического проекта; доступ из workspace проверяется отдельно |
| `gemini` | `.gemini/skills/aispa` | `~/.gemini/skills/aispa` | `GEMINI.md`; общая карта `AGENTS.md` |
| `antigravity` | `.agents/skills/aispa` | `~/.gemini/config/skills/aispa` | `AGENTS.md` / `GEMINI.md`; `.agents/rules/aispa.md` с `trigger: always_on` |

Существующие пользовательские инструкции сохраняются. Инициализация не меняет
глобальные настройки приложений, модель, доступы или правила подтверждения.
Проект должен быть доступен выбранному workspace. Если root проекта отличается,
передавайте его и путь к AGENTS.md явно каждому участнику; подтвердите чтение
этого файла. Установка навыка не переключает workspace приложения.

**Приоритет копий имеет значение.** OpenClaw также читает `<workspace>/skills`
(выше `.agents/skills`) и общий `~/.agents/skills` в стандартном контуре данных.
Gemini читает `.agents/skills` и `~/.agents/skills` как алиасы; внутри одного
уровня они имеют преимущество перед `.gemini/skills`. Поэтому старая общая
копия может перекрыть новую отдельную. До установки проверяйте действующий путь
через каталог среды. [OpenClaw: skills](https://docs.openclaw.ai/tools/skills),
[Gemini CLI: skills](https://geminicli.com/docs/cli/skills/).

**Antigravity:** таблица относится к приложению и IDE. Старый глобальный путь
`~/.gemini/antigravity/skills` поддерживается IDE для совместимости, новый
проектный путь — `.agents/skills` (старый `.agent/skills` также распознаётся).
Отдельный Antigravity CLI использует `~/.gemini/antigravity-cli/skills`:
для него нужен явный `--destination`, а не обещание, что путь приложения
подойдёт всем поверхностям. Нативная работа CLI здесь не проверена.
[Официальные пути](https://www.antigravity.google/docs/skills/).

## Участники, независимость и доступы

| Среда | Откуда брать идентичность участника | Граница проверки |
|---|---|---|
| Codex | Реальный ID агента и сеанс из доступного инструмента создания/управления агентами | Файл роли не создаёт нативного агента |
| Claude Code | Реальный handle/ID нативного субагента и сеанс из ответа или журнала среды | Новое имя роли не доказывает новый контекст |
| Cursor | Реальный ID участника/запуска из доступной функции делегирования | Наличие этой функции зависит от установленной версии и режима |
| OpenClaw | `childSessionKey` и `runId` принятого `sessions_spawn`; дополнительный `sessionId`, если выдан | `agentId` профиля и произвольный `label` не заменяют созданную сессию |
| Gemini CLI | Нативный `agent_id` события запуска плюс `session.id`; сохранять связь с исходным tool call | Один и тот же инструмент роли может создавать разные исполнения; имя инструмента недостаточно |
| Antigravity | Реальный conversation ID созданного субагента из ответа/события среды | Имя определения субагента и выбранная модель не являются ID исполнения |

Для новых сред поля CLI заполняются так (значения берутся из ответа, не из примера):

| Среда | `--native-id` | `--session` |
|---|---|---|
| OpenClaw | `childSessionKey` созданного участника | `runId` его принятого запуска |
| Gemini CLI | `agent_id` события запуска | `session.id` связанного события |
| Antigravity | conversation ID нового участника | тот же conversation ID, если отдельного session ID нет |

Для координатора берите ID его текущей сессии из host; профиль/имя роли
не заменяет сессию. Одно и то же значение в двух полях допустимо только если
это действительно единственный идентификатор исполнения, выданный средой.
Значения переносятся в существующие поля actor/assignment AISpa из настоящего
ответа среды. Нельзя генерировать UUID, подставлять имя роли или помечать
координатора как независимого проверяющего ради прохождения проверки.
Сохранённая квитанция фиксирует заявленное происхождение; она не является
криптографическим подтверждением контекста или поставщика модели.

### OpenClaw

При `disable-model-invocation: true` используйте явный `$aispa` или `/aispa`,
а не свободную фразу с названием: host должен разрешить явную ссылку на навык.
[Правило явного вызова](https://docs.openclaw.ai/tools/skills).

Нативный инструмент `sessions_spawn` создаёт отдельную сессию и возвращает
`childSessionKey` / `runId` после принятия запуска. Для критики выбирайте
изолированный контекст явно, когда доступная схема поддерживает
`context: "isolated"`: у привязанных к треду запусков значение по умолчанию
может означать наследование истории. Принятие запуска ещё не является его
успешным завершением; результат сверяется с тем же дочерним сеансом.
[Session tools](https://docs.openclaw.ai/session-tool).

Права shell/files задаются конфигурацией Gateway, выбранного агента и sandbox.
Рабочая папка Gateway может отличаться от папки клиента или узла. Не меняйте
профиль прав ради AISpa; передайте исполнителю реальные доступные пути и
зафиксируйте недоступные операции. `AGENTS.md` читается из workspace агента;
он содержит инструкции, но не выдаёт инструментам разрешений.
[Workspace](https://docs.openclaw.ai/concepts/agent-workspace).

### Gemini CLI

Локальные субагенты определяются в `.gemini/agents/*.md` либо
`~/.gemini/agents/*.md` и доступны основной модели как инструменты с именами
ролей. Документация описывает отдельный контекст исполнения. Установленная
версия создаёт собственный ID на исполнение и пишет события начала/завершения.
Если host не выдаёт эти события или ID вызывающему агенту, нельзя заменить
их догадкой. [Subagents](https://geminicli.com/docs/core/subagents/).

Проектный файл по умолчанию — `GEMINI.md`. Чтение `AGENTS.md` как нативного
файла зависит от `context.fileName`; AISpa не должен молча менять эту настройку.
Ссылка на общий контекст добавляется в `GEMINI.md`. Инструменты субагента,
политики, shell и доверенные папки проверяются в фактической сессии; наличие
определения роли не подтверждает доступ к каждому инструменту.
[Контекст проекта](https://geminicli.com/docs/cli/gemini-md/).

### Antigravity

Документация приложения описывает `define_subagent` и `invoke_subagent`:
новый субагент стартует без истории разговора родителя, а взаимодействие
адресуется по conversation ID. Вариант workspace `inherit` сам по себе
не означает наследование разговора. Повторное пробуждение уже работавшего
субагента сохраняет его контекст; для свежей независимой проверки нужен новый
участник. Инструменты и разрешения должны существовать в конкретной сессии;
по одному названию приложения их наличие не предполагается.
[Subagents](https://www.antigravity.google/docs/subagents/).

Для правил допустимы обычные `AGENTS.md` / `GEMINI.md`, без YAML. Модульный
`.agents/rules/aispa.md` требует YAML с точным `trigger: always_on`; другие
написания и отсутствие `trigger` могут привести к пропуску правила.
Приложение суммирует правила разных областей; `.agents/rules.json` задаёт
их регистрацию и наследование. Файлы project rules и этот registry в Git-снимке
входят в общие fingerprints AISpa. Внешние импортируемые правила проверяйте
в нативном контексте: локальный hash не подтверждает содержимое удалённого источника.
Настройки доступа к терминалу,
файлам и подтверждениям наследуются средой, а не расширяются навыком.
[Rules](https://www.antigravity.google/docs/rules/).

## Если возможностей среды не хватает

Проверка возможностей выполняется по доступному реестру инструментов текущей
сессии. Если нет shell, записи в требуемый workspace, независимого контекста
либо подтверждаемого ID участника, сообщите конкретный блокер и продолжайте
только доступные независимые части. Нельзя подменять критика самопроверкой,
изменять review policy или выдавать проект за принятый.

Отсутствие параллельности не равно отсутствию независимости: последовательные
свежие нативные контексты допустимы, если host выдаёт их реальные идентификаторы.
Действующая политика проверки и итоговая приёмка по брифу сохраняются при любом runtime;
само название среды не отменяет проверок и не переключает режим.

## Токены и время

Используйте существующий импорт AISpa `usage --file` с его действующей схемой.
Автоматический импорт журналов перечисленных поставщиков этим адаптером
не обещается. Источник, участник, вызов и охват измерения должны быть указаны;
неизвестные поля остаются **unknown**, не нулём и не оценкой «на глаз».
Если нет обязательных input/output/cache счётчиков на конкретный вызов,
не подставляйте нули и не отправляйте неполную запись: участник остаётся
без измерения в отчёте usage. Дополнительные неизвестные поля сохраняются
как null по действующему контракту.

- **OpenClaw:** список субагентов содержит связь с сессией/запуском, длительность
  и доступный `totalTokens`; источник может дополнительно иметь input/output.
  Не выводите отсутствующие раздельные значения из одного итога. Стоимость
  при подписке или локальной модели не следует из счётчика токенов.
- **Gemini CLI:** headless JSON/stream JSON документирует session metadata,
  статистику токенов и API latency. Общая статистика сессии не доказывает
  раздельную стоимость каждого субагента; детализацию берите только из
  реально доступных связанных событий.
  [Headless output](https://geminicli.com/docs/cli/headless/).
- **Antigravity CLI:** документированы `conversation_id`, usage у шагов и
  накопительный usage у результата. Не суммируйте повторно накопительные
  результаты нескольких ходов. Схема CLI не доказывает доступность тех же
  чисел в UI приложения; `/usage` с остатками квоты не заменяет расход токенов.
  [Headless output](https://www.antigravity.google/docs/cli/headless/).

## Границы проверки

Пути и поля выше проверены по указанным первоисточникам; это контракт интеграции,
не подтверждение доступности каждого инструмента в каждой пользовательской сессии.
Инженерные тесты кандидата проверяют CLI, файловые границы и обработку квитанций
на синтетических данных. Они не аутентифицируют модель или контекст host.
Обнаружение SKILL.md не является проверкой исполнения навыка.
Новые полные модельные прогоны этой итерацией не выполняются.
