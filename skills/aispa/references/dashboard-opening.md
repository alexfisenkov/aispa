# Видимое открытие дашборда · 0.3.1

Это обязательное действие агента при явном запуске AISpa, а не настройка,
которую нужно заново согласовывать. Python обслуживает локальный экран;
встроенную вкладку открывает нативный инструмент приложения.

## Порядок

1. Сохрани прежний порядок update-check и начальных выборов режима. Для нового
   проекта нужен успешный init: не выдумывай режим или прогон ради экрана.
2. Сразу после init, resume или возврата к активной работе запусти
   `python3 <pinned-runtime>/tools/aispa.py --root <project> dashboard start`.
   В Windows выбери реально доступный Python. Start переиспользует живую службу.
3. Возьми точный `url`, только когда `running: true`. Если сервер не подтвердился,
   исправь причину и повтори именно dashboard start, не init. Сохрани факт уже
   выполненного init/resume; ошибка экрана не откатывает проект.
4. Открой URL **видимо внутри приложения**. В Codex: `open_in_codex` с
   `target.type: browser`, `target.url` и `placement: right`; либо выданный CUA
   `createBrowserTab("iab", url, {visible: true})`. Не передавай threadId другого
   чата. Повторный вызов должен показать существующую вкладку того же проекта,
   если инструмент позволяет её найти; не плодить вкладки на каждый статус.
   Если инструмент вернул только queued, проверь вкладку; при необходимости
   используй доступный CUA с visible: true. Временную вкладку сохрани через
   поддержанный markDeliverable/markHandoff, чтобы она не закрылась в конце ответа.
5. Прочитай состояние вкладки и убедись, что видны название текущего проекта,
   этап и живые данные. Лишь затем продолжай интервью, discovery, spec, plan
   и задачи. Подтверждение HTTP/процесса само по себе не проверяет UI.

Для Cursor/Antigravity и других графических host используй их фактически
доступную встроенную browser/preview-панель. У терминального клиента может не
быть такой поверхности. Наличие инструмента браузерной автоматизации ещё не
доказывает, что его окно встроено и видно пользователю.

## Честная граница

`requiredHostActions` — требование выполнить следующий нативный шаг, не
доказательство его выполнения. `verification: required` не заменяется
выдуманным `opened: true`. Скриншот headless-страницы, queued-открытие скрытого
чата и сообщение с URL не считаются видимой панелью.

Если вкладка доступна, но открытие не удалось, восстанови сервер/вкладку и
покажи конкретный сбой до дальнейшей работы. Если встроенной поверхности
вообще нет, сообщи это и дай живой URL для ручного открытия; не представляй
это как выполненное требование встроенного браузера и не останавливай
независимую работу молча. Дополнительные приложения/плагины не устанавливай.
Не подменяй встроенный браузер системными open/start/xdg-open/webbrowser.open.

Читай только точный loopback URL из service receipt. Без query-параметров,
`?demo`, архивного accepted.html и секретного control token. Дашборд отображает
ход работы и не является приёмкой продукта. Его опрос продолжает обновляться
в существующей вкладке; повторять открытие на каждую задачу не нужно.

Команды status/context-refresh после явного dashboard stop не поднимают службу.
Возобновление выполняй отдельной командой, затем открывай панель; resume в batch
не допускается, чтобы следующие шаги не прошли раньше нативного открытия.
