# Видимое открытие панели

Это обязательное действие агента при запуске AISpa для разработки, а не
настройка, которую нужно заново согласовывать. Python обслуживает локальный
экран; вкладку открывает нативный инструмент приложения. Audit-only и чтение
`faq` панель не запускают.

## Порядок: один запуск, одно открытие

1. Сохрани прежний порядок update-check и начальных выборов режима. Для нового
   проекта нужен успешный init: не выдумывай режим или прогон ради экрана.
2. `init` и `resume` возвращают в `requiredHostActions` действие
   `start-dashboard` — только запуск, без открытия. Выполни
   `python3 <pinned-runtime>/tools/aispa.py --root <project> dashboard start`.
   В Windows выбери реально доступный Python. Start переиспользует живую службу.
3. Ответ `dashboard start` содержит единственное действие открытия
   `open-dashboard` с точным `url`, только когда служба подтверждена
   (`running: true`). Если сервер не подтвердился, исправь причину и повтори
   именно `dashboard start`, не init. Ошибка экрана не откатывает уже
   выполненный init/resume.
4. Открой этот URL одним действием, без вопроса «открыть ли». Сделай это до
   интервью по существу, разбора брифа, исследования, подготовки документов и
   запуска исполнителей. После resume и возвращения к существующему проекту
   повтори этот порядок.
5. Прочитай состояние вкладки: видны название текущего проекта, этап и живые
   данные, а не demo или архив. Лишь затем продолжай работу. Подтверждение
   HTTP/процесса само по себе не проверяет UI.

## Как открыть в своей среде

- **Codex.** `open_in_codex` с `target.type: browser`, `target.url` и
  `placement: right`. Ответ queued ещё не означает открытие. Перед любым
  повтором проверь, что вкладки этого проекта нет; только тогда используй
  выданный CUA `createBrowserTab("iab", url, {visible: true})`. Найденную
  вкладку показывай и переиспользуй, новую не создавай. Не передавай threadId
  другого чата. Временную вкладку сохрани поддержанным
  markDeliverable/markHandoff, чтобы она не закрылась в конце ответа.
- **Claude Code.** Открой URL в браузере приложения (панель Browser), если он
  есть; иначе (терминальный клиент) один раз дай ссылку и прямо скажи, что
  панель не открыта автоматически. Ссылку на каждом шаге не повторяй.
- **Cursor, Antigravity и другие графические host** — их фактически доступная
  встроенная browser/preview-панель.

Фактическую команду выбирай по реестру инструментов текущей среды; не
придумывай API. Наличие инструмента браузерной автоматизации ещё не доказывает,
что его окно встроено и видно пользователю.

## Честная граница

`requiredHostActions` — требование выполнить следующий нативный шаг, не
доказательство его выполнения. `verification: required` не заменяется
выдуманным `opened: true`. Запуск сервера, ссылка в ответе, скриншот
headless-страницы, queued-открытие скрытого чата не подтверждают видимую
вкладку.

Если вкладка доступна, но открытие не удалось, восстанови сервер/вкладку и
покажи конкретный сбой до дальнейшей работы. Если встроенной поверхности нет,
прямо назови ограничение и дай живой URL; не представляй это как выполненное
открытие и не меняй незаметно браузер. Это ограничение отображения, а не
разрешение отменить требования проекта или ослабить его проверки.
Дополнительные приложения и плагины не устанавливай. Не используй системный
`open`/`start`/`xdg-open`/`webbrowser.open` как замену. Не добавляй к URL
`?demo` либо токен. Открывай только точный loopback URL из ответа службы. Существующий
прогон не пересоздавай ради дашборда. Дашборд показывает ход работы и не
является приёмкой продукта.

## После открытия

Опрос продолжает обновлять ту же вкладку; повторять открытие на каждую задачу
не нужно. Ответ сервера несёт `snapshot.ageSeconds`: при неизменных файлах
журнала сервер отдаёт прежний снимок до 300 с — это не зависание. В скрытой
вкладке опрос стоит и возобновляется при возврате. «Снимок считается» — сервер
отвечает и считает; «Нет связи» — ответа нет дольше 20 секунд.

`dashboard status` показывает состояние службы, `dashboard stop` останавливает
её, `dashboard archive` создаёт отдельный исторический снимок без живого
опроса. Команды status/context-refresh после явного `dashboard stop` службу не
поднимают. `resume` в batch не допускается: после него сначала панель.

## Панель старого закреплённого прогона

Если установленный пакет новее закреплённого runtime прогона, панель поднимай
не закреплённым `dashboard start`, а командой `dashboard refresh-view` из
установленного пакета: `dashboard refresh-view --port <текущий порт>` с тем же
root. Она сохраняет прежний HTML, проверяет старый журнал известной
стабильной версии и запускает совместимый read-only viewer. Все действия
разработки продолжаются pinned runtime. Если проверка чтения отказала, не меняй
журнал вручную ради зелёного экрана. Ошибка status не исправляется
редактированием закреплённых файлов: после сохранённой операции не повторяй
мутацию только из-за ошибки проекции, сверяй текущий viewer. Неподдержанный или
повреждённый журнал остаётся ошибкой; его не переписывают.
