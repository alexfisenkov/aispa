# Новая попытка по решению владельца

Применяй этот маршрут, когда владелец дал новое разрешение повторить проверку
заблокированной задачи в прежнем объёме. Требования, бриф и выбранный режим
проверки сохраняются. Это не новый раунд старой попытки: создаются новая попытка,
карточки и участники; прежние отказы остаются в истории.

Сначала прочитай ответ владельца и вопрос, на который он отвечает. Сохрани
дословный источник в короткий UTF-8 файл. Для ответа вроде «да» источник должен
содержать также точный вопрос с обозначением ролей: «Вопрос ассистента» и
«Ответ владельца». Иначе из сохранённого разрешения нельзя понять его объём.
Не добавляй в источник слова, которых владелец не говорил, и не включай
постороннюю переписку, секреты или личные данные.

Присвой локальной записи решения устойчивый ID. Это ID записи, а не
подтверждение личности или нативный ID сообщения хоста. Не выдумывай такую
аттестацию. Новый ID создаётся только после действительно нового ответа
владельца. Одинаковые слова в разных ответах допустимы; старое решение нельзя
переименовать ради пополнения попыток. Одна запись может разрешать несколько
явно названных задач; для них используются одинаковые источник, SHA и цитата.

Вычисли SHA-256 исходных байтов файла. Если прогон остановлен, сначала вызови
`resume` отдельно: эта команда не входит в `batch`. Открой и проверь его
дашборд по обычному маршруту продолжения. Затем:

```text
new-attempt T01 --owner-source-file <источник> --source-sha256 <SHA-256> --owner-decision-id <ID-записи> --quote "<точные слова владельца>"
```

Команда проверяет заблокированную задачу, её историю, действующий контракт,
план и источник до открытия попытки. Исходные байты копируются в неизменный
артефакт разрешения, связанный с задачей и предыдущей попыткой. Повтор того же
ID для той же задачи запрещён; повтор для другой задачи не допускает подмены
источника или цитаты. Сам движок не удостоверяет, кто написал входной файл:
соответствие реальному ответу проверяет агент и независимый проверяющий.

Бриф не дополняется, `sealed` не снимается, задачи не перепланируются. Новая
попытка сразу получает карточки. Далее назначь нового исполнителя, получи свежий
контекст и выполни `start` до правок. Для ремонта нужны новый настоящий RED,
реализация и GREEN; для проверки уже существующего поведения — честное
намерение по каждому критерию и актуальные проверки. Нельзя переименовать
исторический RED в проверку другого файла. Маршрут критики и приёмки выбранного
режима остаётся обязательным.

Если повторяется отложенный предок и финальная задача, сначала заверши предка,
затем открывай попытку финальной задачи: её карточка должна учитывать актуальные
зависимости. История принятых потомков сохраняется. Реальное изменение их кода
по-прежнему может требовать обновления проверки; этот маршрут не превращает
устаревшее доказательство в PASS.

Если владелец изменил сам объём работы, применяй маршрут изменения брифа и
соответствующие сверки. Прежний `new-attempt --brief B… --quote …` сохранён для
совместимости. Старый закреплённый runtime сам не получает новый интерфейс:
при отсутствии флагов нужен проверенный адресный ремонт, сохраняющий исходную
копию и историю; не редактируй runtime или его digest вручную.
