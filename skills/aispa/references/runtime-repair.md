# Ремонт длинных цитат в активном прогоне 0.3.5

Обычное обновление навыка не заменяет движок уже начатого проекта.
Если `scenarios` отвергает полную зарегистрированную цитату длиннее 1600
символов, AISpa 0.3.6 предоставляет отдельный адресный инструмент.

Он поддерживает только точный опубликованный пакет 0.3.5. Допускается
оригинальный `design_contract.py` либо известная однострочная заплатка этого
дефекта. Все остальные исходные файлы должны совпадать с выпуском.
Кеши Python не копируются; ссылки, неизвестные изменения и повреждённые
источники отклоняются.

## Осмотр

Остановите параллельные команды AISpa для этого проекта. Из установленного
проверенного пакета 0.3.6 выполните:

```text
python3 -B <skillDir>/tools/repair_source_quotes.py --root <projectRoot>
```

На Windows используйте `python -X utf8 -B` или `py -3 -X utf8 -B`.
Осмотр не изменяет файлы. Ответ содержит `run`, `journalSha256`, старый и
новый digest, точный diff и число проверенных артефактов.

## Применение по уже полученному согласию владельца

Сохраните реальные слова владельца, разрешающие этот ремонт, в локальном
UTF-8 файле. Повторно спрашивать не нужно, если согласие уже есть.
Инструмент проверяет байты файла, но не доказывает смысл и авторство согласия.

```text
python3 -B <skillDir>/tools/repair_source_quotes.py --root <projectRoot> --apply --confirm --expected-journal-sha256 <SHA-из-осмотра> --approval-file <approvalFile>
```

Под замком инструмент перечитывает журнал, исходные брифы/спецификацию и
связанные артефакты. Создаёт отдельный `runtime-repairs/<id>/runtime`,
сохраняет исходный журнал и согласие, затем дописывает одно событие
`runtime-repaired:source-quotes-0.3.5` со старым/новым digest и квитанцией.
Версия прогона остаётся 0.3.5; меняется только указанная строка его движка.
Требования, правила проверки, доказательства и прежние строки журнала
сохраняются. Это адресный ремонт, а не перенос истории на 0.3.6.

Продолжайте через **точный путь `cli` из ответа**, передавая прежний
`--root`. Старый runtime остаётся на месте. Неисправленная исходная копия после смены
digest отвергает запись. Если в исходной копии уже была точная разрешённая
заплатка, её байты и digest совпадают с новой и оба пути технически работают;
для продолжения всё равно используйте возвращённый `cli`. Не редактируйте digest или историю руками.
Повторите ранее отклонённую команду scenarios с актуальным отчётом.
Общий PASS проекта от ремонта не появляется. Сохраните путь `cli` в контексте
ведущего агента. После потери контекста его можно повторно получить осмотром
или прочитать `runtimeRepairs[0].runtimePath` в последнем состоянии журнала.

Если дашборд уже запущен, остановите его штатной командой
`dashboard stop`, затем запустите `dashboard start` через новый путь
`cli` и откройте возвращённый URL во встроенном браузере. Старый процесс
держит прежний код в памяти.

## Отказы и прерывания

- Изменился журнал после осмотра — новый осмотр, затем повтор с новым SHA.
- Проект завершён, версия другая, есть незавершённое восстановление или
  неизвестные изменения runtime — ремонт отклоняется.
- Неполный stage до записи события не выбирается как рабочий runtime.
  Исходная копия сохранена; повтор после свежего осмотра создаёт новый stage.
- При оборванной строке журнала сначала действует штатное восстановление
  журнала; не дописывайте и не удаляйте его строки вручную.
- Повтор подтверждённого ремонта не создаёт второе событие. После последующих
  событий нужен свежий SHA; проверяется тот же файл согласия.

Проверка сохранённых SHA доказывает сохранность артефактов, а не качество
продукта. Внешние ссылки на рабочий код и другие прогоны отмечаются отдельно
и не объявляются заново проверенными.
