# Большие входы, отчёты и ресурсные бюджеты

Политика `scalableInputs` закрепляется только новым `init`. Действующие pinned
runtime и журнал не заменяются. Прежние политики сохраняют прежние доменные
потолки; монолитные входы остаются допустимыми. Новая политика сохраняет все
исходные ID, точные цитаты, критерии и связи: размер проекта не разрешает
удалять условия или принимать непроверенный остаток.

## Общий транспорт

Штатная подготовка без создания прогона:

```bash
python3 skills/aispa/tools/aispa.py pack --file input.json --output bundle.json --kind json
python3 skills/aispa/tools/aispa.py --root PROJECT requirements --file bundle.json
```

`pack` поддерживает `--basis SHA256` и `--chunk-bytes N`, выполняет read-back
и возвращает file/SHA, полный digest, bytes и число частей. Бриф использует
`--kind text`. Команда не меняет журнал и не заменяет существующий output.
`--chunk-bytes` не должен превышать действующий `AISPA_CHUNK_BYTES`: producer
проверяет это до создания каталога, частей и манифеста. Отказ `RESOURCE_LIMIT
chunkBytes` позволяет увеличить бюджет читателя или уменьшить размер части и
повторить команду с тем же output.

`aispa_core.scale.write_manifest(path, raw, kind="json"|"text", basis=SHA256,
chunk_bytes=...)` принимает UTF-8 bytes. Он записывает части, затем манифест.
При ошибке записи убираются только созданные этим вызовом файлы. Существующий
манифест не заменяется. Переданный `basis` — связь конкретного пакета; доменный
`basis` внутри JSON отдельно проверяет действующий валидатор команды.

Манифест schema 1 содержит `aispaManifest: 1`, `kind`, `basis`, `digest`,
`totalBytes` и полный упорядоченный `chunks`. Каждая ссылка имеет `file`,
`sha256`, `index`, `bytes`. JSON части содержит schema, kind, basis, digest,
index, total и base64 content. Разбиение идёт по байтам, включая середину
многобайтного символа; UTF-8 декодируется после восстановления всей строки.
Общий digest — SHA-256 точных исходных bytes; SHA манифеста связывает порядок,
длины и SHA всех частей. Пути частей относительны манифесту, без выхода,
скрытых/секретных имён и символических ссылок.

`Workflow.read_input` восстанавливает весь пакет до доменной валидации.
Тот же маршрут используется для брифа, требований, идеи, сценариев,
интерфейсов, плана, test-intent, coverage/task/wave/blind/final отчётов.
Пакет не является отдельным разрешением, сокращённым планом или доказательством.
Повторные ID, неизвестные ссылки, циклы и неполное покрытие проверяются по
целому восстановленному значению, включая границы частей.

Крупные новые domain artifacts и sections контекста сохраняются этим же
транспортом. `Journal.text(ref)` восстанавливает содержимое;
`artifact_valid` проверяет внешнюю SHA **и все части**. Испорченная последняя
часть снимает актуальность доказательства при неизменном манифесте.
Исторические обычные файлы не переписываются. Прямые читатели истории между
прогонами должны быть переведены на этот reader до приёмки всей версии;
это обязательная миграция следующего среза продолжения, а не текущий PASS
всех межверсионных сценариев.

## Бюджет отдельной операции

Профиль задаётся положительными конечными значениями окружения:

| Переменная | По умолчанию | Что ограничено |
| --- | ---: | --- |
| `AISPA_MAX_INPUT_BYTES` | 67108864 | bytes одного полного входа/восстановленного отчёта |
| `AISPA_MAX_MANIFEST_BYTES` | 8388608 | bytes метаданных манифеста, проверяются и при построении списка частей |
| `AISPA_CHUNK_BYTES` | 1048576 | bytes декодированной части и порог пакетной записи |
| `AISPA_MAX_MEMORY_BYTES` | 536870912 | консервативная оценка материализации входа: четыре его byte-size |
| `AISPA_MAX_INTENT_REVISIONS` | 16 | операционный бюджет ревизий одного test-intent; отдельно от числа задач/требований |
| `AISPA_OPERATION_SECONDS` | 120 | deadline чтения/пакетирования и контрольных точек проверки |
| `AISPA_DISCOVERY_PAGE_SOURCES` | 48 | число источников на одной странице |
| `AISPA_DISCOVERY_EXCERPT_CHARS` | 96000 | Unicode code points фрагмента источника |
| `AISPA_DISCOVERY_PAGE_CHARS` | 96000 | Unicode code points текста страницы discovery |

Bytes и Unicode code points различаются. Профиль памяти — проверяемая оценка
буфера декодирования, **не ограничитель RSS процесса**. JSON-объекты,
глобальные индексы зависимостей и полный снимок журнала занимают дополнительную
конечную память. Парсер JSON не прерывается посреди вызова: deadline проверяется
до и после него. Эти ограничения не означают неограниченную память или время
произвольной внешней команды. История остаётся полноснимочной; delta-журнал
этим изменением не вводится.

Отказ `RESOURCE_LIMIT` называет бюджет, путь, прогресс и продолжение:
увеличить конкретный бюджет и повторить **полный** вход. Неполный scope не
принимается. Ввод читается ограниченными блоками, проверка размера выполняется
до чтения файла целиком; рост после stat тоже выявляется. Профиль не отменяет
секретность, confined paths, доменную схему или существующие guards.

Прогресс транспорта и чтения обозначается `completedBytes`, обхода DAG и
списка расширения зон — `completedItems`. Это число обработанных элементов
на момент отказа, а не разрешение принять часть графа или плана.

Новые scalable-квитанции расширения зон имеют schema 2: нет отдельных потолков
8 эпох/32 файла, весь запрос и история проходят byte/time/memory бюджеты.
Schema 1 сохраняет прежнюю трактовку 8/32; старый журнал не получает новую
ёмкость от одного только современного reader. Все ID, исходные критерии,
точные пути, CAS и история попытки остаются обязательными. Подробности —
[task-zone-extension.md](task-zone-extension.md).

Discovery с `scalableInputs` использует общий ограниченный reader и проверяет
четырёхкратный размер исходных UTF-8 bytes до открытия файла. Учёт удерживаемой
страницы включает выбор источников, fingerprints и уже сохранённые excerpts;
они уменьшают доступную память следующего чтения. Временный полный исходник
освобождается перед следующим. Рост после stat читается только в пределах
оставшегося бюджета плюс один байт для выявления переполнения. Полный итоговый
снимок также проходит ресурсную проверку до записи коллекции.

Ресурсный отказ discovery выходит как `RESOURCE_LIMIT` с продолжением; он не
превращается в `unavailable-or-symlink` или молчаливый пропуск include.
Повтор с достаточным бюджетом сохраняет весь запрошенный источник. Сканирование
исторической политики сохраняет свои прежние лимиты и правила фрагментов.

В `failureChecks` нового прогона нет отдельного потолка числа сценариев и
длины их ID, точного criterion или пояснений. Весь контракт проверяется по
операционным бюджетам; уникальность ID, точные критерии, пять отказных границ
и привязка к исходникам RED сохраняются. Историческая политика продолжает
использовать прежние пределы 24 сценариев и 1600 символов текста.

Для mixed test-intent приём нового контракта и проверка его истории используют
явную политику прогона: прежняя политика сохраняет 4096 способов проверки и
1600 символов в `reason`, `procedure`, `expected`. Потребитель уже сохранённого
неизменного контракта проверяет структуру, точные пары criterion/kind, полноту
и привязку к источнику. Без state он не применяет исторические пределы заново
к контракту, принятому по `scalableInputs`. Это не отменяет проверку политики
при приёме или валидации истории и не превращает `not_tested` в PASS.

## Адресное чтение

`page --file INPUT [--field LIST_FIELD] [--limit N] [--cursor CURSOR]` читает
монолит или manifest и возвращает `items`, `total`, `omitted`, `cursor`,
`digest`. Cursor связан с полным упорядоченным списком; изменение списка делает
его недействительным. Страница — представление; валидатор команды всё равно
читает весь исходный документ. Полные sections имеют собственные file/SHA.

Компактный разбор идеи сохраняет лимит представления 8000 символов JSON.
Длинный summary показывается префиксом, а `omitted.summaryChars` указывает
точное число пропущенных Unicode code points. Поле `artifact` содержит file/SHA
полного неизменного отчёта; `idea --full` возвращает его целиком. Пропуск
представления не меняет критерии, историю или сохранённые исходные bytes.

`discover --include PATH ... [--cursor CURSOR]` сохраняет адресную страницу
источников. Явные безопасные include идут первыми. `pagination` показывает
полное число кандидатов, остаток, cursor и digest; `excerptStart`, `excerptEnd`,
`totalChars` позволяют продолжить внутри большого источника. Следующая страница
заново проверяет fingerprint выбора и отвергает cursor после изменения источника.
Каждая выданная страница получает неизменную ссылку, даже если следующий запрос
обновил текущий discoveryCollection. Название в include без прочитанного
фрагмента не считается изученным источником.

## Проверка

Адресные регрессии: `PYTHONPATH=tests python3 -B -m unittest tests.test_scale.ScaleTests tests.test_scale.ScaleMixedConsumerTests -v`.
Набор проверяет 300 требований, 110 задач, полный preparation/report путь,
1500 зависимостей, Unicode byte splits, inline/manifest parity, потерянные,
подменённые, повторные, чужие и выходящие за границу части; отказ ресурса без
принятой мутации; cursor integrity и все 60 явных discovery include.
Это synthetic code evidence; поведение модели, CI, новый выпуск и межверсионный
carryover требуют своих свидетельств.
Mixed consumer-регрессии дополнительно проверяют 4097 способов, каждое поле
пояснения длиной 1601 символ, живой и сохранённый отчёт, прежние ограничения,
структурные отказы и повреждение источника без изменения истории.
`ScaleDiscoveryBudgetTests` и `tests/test_discovery_budget.py` проверяют отказ
до открытия источника, совокупную память страницы, ограниченное чтение при
росте после stat, UTF-8 bytes, полный повтор и прежнюю политику. Тестовые
источники используют канонические пути, включая macOS `/var` / `/private/var`.
